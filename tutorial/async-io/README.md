# असमकालिक HTTP और डेटाबेस (Asynchronous HTTP and database I/O)

असमकालिक कार्य (Async task) का लाभ तब मिलता है जब किसी उत्तर की प्रतीक्षा करते समय अन्य कार्य आगे बढ़ सकें। `असमकालिक` फलन लिखना पर्याप्त नहीं है: नेटवर्क और डेटाबेस के लिए नीचे दिए असमकालिक अनुकूलक चुनें। `प्रतीक्षा` वर्तमान कार्य को रोकती है; पूरा प्रेषक नहीं रुकता। CPU पर लंबी गणना अपने-आप समानांतर नहीं होती।

## HTTP अनुरोध (HTTP request)

```bhash
आयात मानक.एचटीटीपी;
आयात मानक.एचटीटीपीउत्तर;
असमकालिक फलन मुख्य()->शून्य {
    स्थिर क:कार्यफल<एचटीटीपीउत्तर> = एचटीटीपी.पाओअसमकालिक("https://example.com/");
    स्थिर उत्तर:एचटीटीपीउत्तर=प्रतीक्षा क;
    लिखो(उत्तर.स्थिति());लिखो(उत्तर.पाठ्यांश());
}
```

अनुरोध विन्यास (Request configuration) के लिए `एचटीटीपीअनुरोध` बनाकर `भेजोअसमकालिक(अनुरोध)` बुलाएँ। `समयसीमा`, `शीर्ष`, `सामग्री` और `अनुसरणसीमा` के नियम पुराने HTTP API जैसे हैं। बुलाते समय अनुरोध की प्रति बनती है; बाद में मूल बफ़र बदलने से चल रहा अनुरोध नहीं बदलता। दो स्वतंत्र कार्य पहले बनाएँ और फिर दोनों की प्रतीक्षा करें, ताकि उनके नेटवर्क कार्य साथ आगे बढ़ सकें।

निरस्तीकरण (Cancellation) के लिए `निरस्तीकरणस्रोत` का `चिह्नलो()` अंतिम तर्क दें। `निरस्तकरो()` के बाद कार्य की प्रतीक्षा करके `निरस्तअपवाद` पकड़ें। संसाधन बंद होने तक सफाई पूरी होती है। सर्वर तक पहुँचा परिवर्तन वापस होने की गारंटी नहीं है।

## डेटाबेस संबंध (Database connection)

[`sqlite.bhash`](sqlite.bhash) पूरा चलने योग्य उदाहरण है। इसे JVM, CLR या native पर चलाएँ:

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run tutorial/async-io/sqlite.bhash
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run tutorial/async-io/sqlite.bhash --target clr
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run tutorial/async-io/sqlite.bhash --target native
```

संसाधन क्षेत्र (Resource scope) में `असमकालिक संसाधन` लिखें। संबंध खोलना, कथन तैयार करना, चलाना, पहली पंक्ति प्राप्त करना और बंद करना सभी प्रतीक्षा योग्य हैं। पंक्ति मिलने के बाद उसके मान पढ़ना स्थानीय कार्य है, इसलिए getter पर `प्रतीक्षा` नहीं लगती।

मापदंडयुक्त SQL (Parameterized SQL) में `?` रखें और `पूर्णांकरखो`, `पाठरखो` आदि से मान बाँधें। उपयोगकर्ता का पाठ SQL में जोड़कर न बनाएँ। बंधन क्रमांक १ से, स्तंभ क्रमांक ० से शुरू होते हैं। `बाइटरखो` बफ़र की प्रति रखता है। `रीसेट()` की प्रतीक्षा करके कथन दोबारा चला सकते हैं; `बंधनमिटाओ()` पुराने बंधन हटाता है।

लेनदेन (Transaction) में कई बदलाव एक साथ सहेजे जाते हैं। `सहेजो()` की सफल प्रतीक्षा के बाद ही सफलता बताएँ। क्षेत्र से बिना commit निकले तो बंद होते समय rollback होता है। एक संबंध पर एक समय में एक ही क्रिया चलाएँ; स्वतंत्र काम के लिए अलग संबंध लें।

PostgreSQL प्रदाता (PostgreSQL provider) चुनने के लिए `पोस्टग्रेसविन्यास` में मेज़बान, पोर्ट, डेटाबेस, उपयोगकर्ता, गुप्तशब्द और CA प्रमाणपत्र भरें, फिर `प्रतीक्षा असमडेटा.पोस्टग्रेस(विन्यास)` बुलाएँ। उसके बाद कथन और लेनदेन का API वही है। गुप्तशब्द स्रोत में न रखें; परिवेश/सुरक्षित विन्यास से लें। TLS का सुरक्षित `verify-full` विन्यास बनाए रखें। JVM में चालक साथ आता है; CLR/native पर libpq 14+ रनटाइम चाहिए।

अज्ञात परिणाम (Unknown commit outcome) सामान्य असफलता से अलग है। commit भेजने के बाद संपर्क टूट जाए तो `लेनदेनपरिणामअज्ञातअपवाद` मिल सकता है। वही लेनदेन आँख बंद करके दोहराने से दोहरा भुगतान/दोहरी प्रविष्टि हो सकती है। नए संबंध से टिकाऊ पहचान द्वारा स्थिति जाँचें।

सीमाएँ (Limits): एक परिणाम अधिकतम १,०२४ पंक्तियाँ और ८ MiB तार्किक मान रखता है। बड़े परिणाम के लिए SQL में pagination करें। पंक्तियाँ लोड होने के बाद `स्तंभसंख्या()` और `स्तंभनाम()` उपलब्ध हैं। यह स्ट्रीमिंग cursor नहीं है। ब्राउज़र/playground में ये desktop APIs उपलब्ध नहीं हैं; डेटाबेस तक पहुँच अपने प्रमाणीकृत HTTP backend से दें।

पूरा अनुबंध और वितरण विवरण: [async-io.md](../../docs/async-io.md)।

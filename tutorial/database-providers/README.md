# साझा डेटाबेस और माइग्रेशन

## प्रदाता (Database provider)

`डेटासंबंध` एक साझा अनुबंध है। स्थानीय फ़ाइल के लिए `डेटा.एसक्यूलाइट("tasks.db")` और सर्वर के लिए `डेटा.पोस्टग्रेस(विन्यास)` उपयोग करें। इससे संसाधन, कथन और लेनदेन का उपयोग समान रहता है; SQL की दोनों बोलियाँ पूरी तरह समान नहीं हो जातीं। उदाहरण के लिए PostgreSQL में प्रकार स्पष्ट होते हैं।

## संबंध विन्यास (Connection configuration)

```bhash
आयात मानक.पोस्टग्रेसविन्यास;
आयात मानक.विन्यास;
स्थिर व: पोस्टग्रेसविन्यास = नया पोस्टग्रेसविन्यास();
व.मेज़बान="db.example.org";
व.डेटाबेस="tasks";
व.उपयोगकर्ता="tasks_app";
व.गुप्तशब्द=विन्यास.परिवेश("TASKS_DB_PASSWORD","");
व.प्रमाणपत्र="/etc/tasks/database-ca.pem";
```

यह खंड मुख्य फलन में रखें। सामान्य पोर्ट `५४३२`, संबंध समयसीमा `१०` सेकंड तथा कथन समयसीमा `३००००` मिलीसेकंड है। `सुरक्षा` का सामान्य मान `verify-full` प्रमाणपत्र और मेज़बान दोनों जाँचता है। केवल अलग स्थानीय परीक्षण सर्वर के लिए स्पष्ट `disable` चुनें। गुप्तशब्द को स्रोत, Git या लॉग में न रखें। ब्राउज़र playground से सीधा डेटाबेस संबंध उपलब्ध नहीं है; HTTP सेवा के पीछे डेटाबेस रखें।

## मापदंड वाले कथन (Parameterized statements)

`ड.तैयार(SQL)` एक कथन लौटाता है। SQL में मान जोड़ने के बजाय `?` रखें। बंधन का क्रम **१ से**, परिणाम स्तंभ का क्रम **० से** आरंभ होता है। `बंधनसंख्या()`, `स्तंभसंख्या()` और `स्तंभनाम(क्रम)` मेटाडेटा देते हैं।

| मान | बंधन | परिणाम |
|---|---|---|
| पूर्णांक | `पूर्णांकरखो(१,४२)` | `पूर्णांकलो(०)` |
| दशमलव | `दशमलवरखो(१,१.२५)` | `दशमलवलो(०)` |
| तार्किक | `तार्किकरखो(१,सत्य)` | `तार्किकलो(०)` |
| पाठ | `पाठरखो(१,"भारत😀")` | `पाठलो(०)` |
| बाइटबफ़र | `बाइटरखो(१,बफ़र)` | `बाइटलो(०)` |
| SQL NULL | `रिक्तरखो(१)` | `रिक्तहै(०)` |

`प्रकार(०)` वर्तमान मान का प्रकार देता है। PostgreSQL `NUMERIC` को `सटीकदशमलव` बताता है और `पाठलो` से मूल सटीक अंक देता है; उसे स्वतः binary floating point में नहीं बदलता। तारीख/समय को `समय` और पाठ रूप में लौटाया जाता है। विशेष PostgreSQL प्रकारों के लिए SQL में स्पष्ट cast करें।

`चलाओ()` INSERT/UPDATE/DELETE में प्रभावित पंक्तियों की संख्या लौटाता है। SELECT अथवा RETURNING में `अगला()` से पंक्ति पर आएँ, फिर मान पढ़ें। `रीसेट()` पुनः चलाने देता है और पुराने बंधन रखता है; `बंधनमिटाओ()` उन्हें हटाता है। हर मापदंड बाँधना आवश्यक है। `संसाधन` खंड समाप्त होने पर `बंदकरो()` अपने आप चलता है। लौटाया बाइटबफ़र कथन बंद होने के बाद भी स्वतंत्र रहता है।

## लेनदेन (Transaction)

```bhash
संसाधन (ल: डेटालेनदेन = ड.लेनदेन()) {
    संसाधन (क: डेटाकथन = ड.तैयार("INSERT INTO tasks(id,title) VALUES (?,?)")) {
        क.पूर्णांकरखो(१,२); क.पाठरखो(२,"नया काम"); क.चलाओ();
    }
    ल.सहेजो();
}
```

`सहेजो()` commit करता है। `वापसलो()` rollback करता है। सहेजे बिना बाहर निकलने पर rollback होता है, अपवाद आने पर भी। विफल PostgreSQL लेनदेन को सहेजना अस्वीकार होता है। SQL में BEGIN/COMMIT भेजने के बजाय यही API उपयोग करें। Nested transactions अभी समर्थित नहीं हैं।

## क्रमबद्ध बदलाव (Migrations)

साथ का [migrations.bhash](migrations.bhash) पूरा चलने योग्य उदाहरण है। पहले बदलाव में तालिका बनती है, दूसरे में नया स्तंभ जुड़ता है। दोनों संस्करणों को Git में रखें।

1. `माइग्रेशन(संस्करण,नाम,कथनोंकीसूची)` बनाएँ। संस्करण सकारात्मक और बढ़ते क्रम में हों।
2. `माइग्रेशनयोजना` सूची की स्वतंत्र प्रति रखती है।
3. `स्थिति(ड)` लागू/बाकी बदलाव बताता है; `जाँचो(ड)` इतिहास के नाम, क्रम और SHA-256 की जाँच करता है। पहली बार ये इतिहास तालिका बना सकते हैं।
4. `लागूकरो(ड)` सारे बाकी बदलाव और उनका इतिहास एक ही लेनदेन में सहेजता है। त्रुटि पर पूरा नया बैच वापस होता है। दो प्रक्रियाओं में PostgreSQL advisory lock और SQLite write lock लागू करने का क्रम सुरक्षित रखते हैं।
5. पहले लागू हो चुके कथन को संपादित न करें; नया संस्करण जोड़ें। बदला checksum या अनुप्रयोग से नया इतिहास मिले तो कार्य रुकता है। स्वतः downgrade नहीं होता।

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run tutorial/database-providers/migrations.bhash --target jvm
```

उसी फ़ाइल पर `--target clr` अथवा `--target native` चलाएँ। `tasks.db` में डेटा बचता है; दूसरी बार लागू बदलावों की संख्या शून्य होगी। PostgreSQL में संबंध बनाने की पंक्ति बदलें और विन्यास जोड़ें। उत्पादन से पहले बैकअप लें तथा परीक्षण प्रति पर माइग्रेशन चलाएँ।

## वितरण (Runtime distribution)

JVM JAR में सत्यापित PostgreSQL JDBC और उसकी लाइसेंस सूचनाएँ सम्मिलित होती हैं। .NET तथा native में PostgreSQL 14+ का `libpq` client runtime चाहिए। Linux पर `libpq5`, macOS पर PostgreSQL client package, Windows पर PostgreSQL client DLLs स्थापित करें। आवश्यकता हो तो `BHASH_LIBPQ` में library का पूर्ण पथ दें। Native को JVM/.NET या development headers नहीं चाहिए। विस्तृत अनुबंध और सीमाएँ [database-providers.md](../../docs/database-providers.md) में हैं।

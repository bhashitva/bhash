# पहचानकर्ता और हिन्दी टंकण (Identifiers and Hindi input)

पहचानकर्ता (Identifier) किसी चर, फलन, वर्ग, सदस्य या संकुल का नाम है। भाष में अलग-अलग कीबोर्ड से लिखे गए नामों की तुलना करने के लिए `bhash-devanagari-1` नियमावली है। यह नियमावली Unicode 18.0.0 पर आधारित है।

[पूरा चलाने योग्य उदाहरण](identifiers.bhash) में वर्ग, अभिलेख, संवृति, नुक़्ता, जोड़-चिह्न और विस्तारित अक्षर हैं। इसे JVM, CLR और native लक्ष्य पर चला सकते हैं।

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run tutorial/unicode-identifiers/identifiers.bhash
```

## नाम में कौन-से अक्षर लिख सकते हैं

आरंभिक अक्षर (Starting character) स्वीकृत देवनागरी या देवनागरी के साथ प्रयुक्त साझा लिपि का अक्षर होना चाहिए। उसके बाद स्वीकृत अक्षर, मात्राएँ, चिह्न, `०` से `९`, `0` से `9` और `_` लिख सकते हैं। नियमावली में वैदिक और विस्तारित देवनागरी अक्षर भी हैं। संख्यात्मक शाब्दिक मानों के लिए अंकों को मिलाने के पुराने नियम अलग से लागू होते हैं।

```bhash
मान कुल_अंक२: पूर्णांक = ५;
लिखो(कुल_अंक२);
```

इस नियमावली में १०२ आरंभिक अक्षर और २०५ सामान्य अनुवर्ती अक्षर हैं। दो अदृश्य जोड़-चिह्न विशेष संदर्भ में स्वीकार्य हैं। सटीक सूची और निर्णय [पहचानकर्ता निर्णय](../../docs/unicode-identifiers-decisions.md) तथा [सभी परिवर्तित अक्षरों की सूची](../../docs/unicode-identifiers-repertoire-review.md) में हैं।

## नुक़्ते की समतुल्य वर्तनी (Canonical equivalence)

कुछ अक्षर एक Unicode code point से या मूल अक्षर और नुक़्ते के अलग code points से लिखे जा सकते हैं। उदाहरण में `क़` का code point U+0958 है। दूसरी वर्तनी `क़` में U+0915 और U+093C हैं। भाष दोनों को एक नाम मानता है।

```bhash
स्थिर क़दम: पूर्णांक = ७;
लिखो(क़दम);
```

इसका परिणाम `७` है। दोनों वर्तनियों से एक ही कार्यक्षेत्र में दो चर घोषित करने पर दोहरी घोषणा की त्रुटि आती है। सामान्य आंतरिक कार्यक्षेत्र में उसी नाम का स्थानीय चर घोषित करने के नियम लागू रहते हैं।

Unicode सामान्यीकरण (NFC normalization) केवल उन वर्तनियों को समतुल्य बनाता है जिनकी canonical equivalence निर्धारित है। `क्ष` में `क`, हलंत और `ष` हैं। `ज्ञ` में `ज`, हलंत और `ञ` हैं। फ़ॉन्ट इन क्रमों को संयुक्त रूप में दिखा सकता है। हर देखने में मिलता-जुलता अक्षर अपने-आप उसी नाम में नहीं बदलता।

## जोड़-चिह्न (ZWJ and ZWNJ)

कुछ हिन्दी कीबोर्ड संयुक्त अक्षर का रूप नियंत्रित करने के लिए U+200D ZERO WIDTH JOINER या U+200C ZERO WIDTH NON-JOINER डालते हैं। भाष में ये केवल इस क्रम में नाम के भीतर स्वीकार्य हैं।

`स्वीकृत अक्षर → वैकल्पिक नुक़्ता → हलंत → एक जोड़-चिह्न → स्वीकृत अक्षर`

उदाहरण में इन code-point क्रमों से बने नाम एक ही नाम हैं।

| वर्तनी | आरंभ का code-point क्रम |
| --- | --- |
| `क्षेत्र` | U+0915 U+094D U+0937 |
| `क्‍षेत्र` | U+0915 U+094D U+200D U+0937 |
| `क्‌षेत्र` | U+0915 U+094D U+200C U+0937 |

```bhash
स्थिर क्‍षेत्र: पूर्णांक = ९;
लिखो(क्षेत्र);
```

इसका परिणाम `९` है। शब्द के शुरू या अंत में, हलंत के बिना, या लगातार दो जोड़-चिह्न लिखने पर त्रुटि आती है। ऐसे नाम की त्रुटि में code point दिखाया जाता है ताकि अदृश्य अक्षर पहचाना जा सके।

आरक्षित शब्द (Keyword) की समतुल्य वर्तनी भी आरक्षित रहती है। उदाहरण के लिए `वर्‍ग` और `वर्ग` दोनों वर्ग की घोषणा करते हैं। जोड़-चिह्न डालकर आरक्षित शब्द को चर का नाम नहीं बना सकते।

## पाठ का वास्तविक मान (Literal text)

नामों की तुलना और पाठ के मान की तुलना अलग भाषा-क्रियाएँ हैं। पाठ में जो Unicode अक्षर लिखते हैं वे उसी रूप में सुरक्षित रहते हैं।

```bhash
लिखो("क़" == "क़");
लिखो("क्‍ष");
```

पहली पंक्ति `असत्य` लिखती है। दूसरी पंक्ति अपने U+200D चिह्न सहित पाठ लिखती है। फ़ाइल, JSON, SQL मापदंड और HTTP सामग्री में भी यही पाठ-संरक्षण लागू होता है।

## त्रुटि और संपादक सहायता (Diagnostics and editor assistance)

| कोड | अर्थ |
| --- | --- |
| BH1002 | नाम का पहला अक्षर या चिह्न अमान्य है |
| BH1003 | ZWJ या ZWNJ का स्थान अमान्य है |
| BH1004 | नाम में कोई अनुवर्ती अक्षर या अदृश्य चिह्न असमर्थित है |
| BH6002 | परियोजना की दो स्रोत फ़ाइलों के नाम एक ही पहचान दर्शाते हैं |

VS Code में त्रुटि का मूल स्थान रेखांकित होता है। उपलब्ध होने पर अमान्य जोड़-चिह्न हटाने का सुधार दिखता है। किसी समान नाम की घोषणा से टकराव दिखे तो पहले नामों की समीक्षा करें। Completion पूरे मूल नाम की सीमा का उपयोग करता है, जिसमें जोड़-चिह्न और supplementary Unicode अक्षर भी शामिल हैं। Watch में भी समतुल्य नामों से मान देख सकते हैं।

Jupyter में एक कक्ष में घोषित scalar नाम अगले कक्षों में समतुल्य वर्तनी से उपलब्ध है। नाम का रूप बदलने से `स्थिर` बंधन को नया मान देने की अनुमति नहीं मिलती। कक्षों के अन्य कार्यक्षेत्र नियम [Jupyter मार्गदर्शिका](../../editors/jupyter/README.md) में हैं।

## फ़ाइलों के नाम (Source filenames)

परियोजना में ऐसे दो स्रोत पथ रखने से बचें जिनकी नाम-पहचान Unicode नियमों से एक हो जाती है। भाष ऐसे पथ मिलने पर दोनों फ़ाइलों का स्थान दिखाता है। फ़ाइल का वास्तविक नाम और उसकी सामग्री सुरक्षित रखी जाती है। संकुल के आयात की पहचान उसके स्रोत में घोषित नामों से होती है।

U+0953 DEVANAGARI GRAVE ACCENT और U+0954 DEVANAGARI ACUTE ACCENT को पहले से स्वीकार्य अनुवर्ती चिह्नों के रूप में बनाए रखा गया है। U+02BC MODIFIER LETTER APOSTROPHE एक स्वीकृत साझा अक्षर है। U+20F0 COMBINING ASTERISK ABOVE केवल नाम के भीतर स्वीकार्य साझा मात्रा-चिह्न है। ये क्रमशः ASCII `'` और `*` से अलग code points हैं।

निर्माण संबंधी विवरण [स्वीकृत डिज़ाइन](../../docs/unicode-identifiers-design.md), [अंतिम निर्णय](../../docs/unicode-identifiers-decisions.md), और [प्रोफ़ाइल manifest](../../docs/identifier-profile.json) में हैं। Unicode के मूल संदर्भ [UAX #31](https://www.unicode.org/reports/tr31/tr31-45.html), [UAX #15](https://www.unicode.org/reports/tr15/tr15-58.html), और [UTS #39](https://www.unicode.org/reports/tr39/tr39-34.html) हैं।

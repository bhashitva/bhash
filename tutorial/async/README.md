# असमकालिक फलन और कार्यफल

असमकालिक निष्पादन (Asynchronous execution) का अर्थ है कि प्रतीक्षा करते समय
क्रमानुदेश दूसरे तैयार काम को चलने देता है। Bhash के अपने फलन एक ही निष्पादन
थ्रेड पर चलते हैं। यह सुविधा CPU के भारी काम को अपने आप समानान्तर नहीं चलाती।

## फलन को रोककर बाद में आगे बढ़ाना

असमकालिक फलन (Async function) के पहले `असमकालिक` लिखें। उसके घोषित परिणाम
का प्रकार शरीर द्वारा लौटाए जाने वाले मान का प्रकार है। उसे बुलाने पर
`कार्यफल<T>` (Task) मिलता है। शरीर अगली उपलब्ध बारी में चलता है।

```bhash
असमकालिक फलन दोगुना(अंक: पूर्णांक) -> पूर्णांक {
    प्रतीक्षा मानक.कार्य.विलंब(१०);
    लौटाओ अंक * २;
}

असमकालिक फलन मुख्य() -> शून्य {
    स्थिर उत्तर: कार्यफल<पूर्णांक> = दोगुना(२१);
    लिखो("काम आरम्भ हुआ");
    लिखो(प्रतीक्षा उत्तर);
}
```

प्रतीक्षा (Await) पूरा हो चुका कार्य मिलने पर भी दूसरे तैयार काम को अवसर देती
है। एक कार्यफल की कई बार प्रतीक्षा की जा सकती है। उसके असफल होने पर मूल
अपवाद फिर मिलता है। `कार्यफल<शून्य>` बिना परिणाम वाला कार्य है। कार्यफल को
किसी बंधन में रखें, लौटाएँ या उसकी प्रतीक्षा करें; फलन के परिणाम को चुपचाप
छोड़ देने पर संकलक त्रुटि देता है।

`प्रतीक्षा अ + ब` का अर्थ `(प्रतीक्षा अ) + ब` है। निर्माणकर्ताओं और साधारण
तुल्यकालिक फलनों में `प्रतीक्षा` उपलब्ध नहीं है। असमकालिक क्रमानुदेश के लिए
`असमकालिक फलन मुख्य() -> शून्य` प्रवेश बिन्दु रखें।

## समय और दूसरे कार्यों को अवसर देना

विलंब (Delay) के लिए `मानक.कार्य.विलंब(मिलीसेकंड)` का प्रयोग करें। यह
पूरे निष्पादन थ्रेड को नहीं रोकता। अवधि ० से २१४७४८३६४७ मिलीसेकंड तक हो सकती
है। अवधि फलन बुलाते समय से मापी जाती है; वास्तविक वापसी तैयार कार्यों और
सफ़ाई में लगने वाले समय के कारण बाद में हो सकती है।

अवसर देना (Yield) के लिए `प्रतीक्षा मानक.कार्य.छोड़ो();` लिखें। लम्बे गणना
वाले चक्र में इसे उचित अन्तराल पर रखें। बिना प्रतीक्षा वाला अनन्त चक्र
सहकारी निरस्तीकरण को भी चलने का अवसर नहीं देता।

## निरस्तीकरण और समयसीमा

निरस्तीकरण स्रोत (Cancellation source) अनुरोध करता है; उससे मिला चिह्न
(Cancellation token) अनुरोध को पढ़ता है। अनुरोध किसी थ्रेड को बलपूर्वक नहीं
मारता। `चिह्न.जाँचो()` सुरक्षित स्थान पर निरस्तीकरण स्वीकार करता है।

```bhash
आयात मानक.निरस्तअपवाद;

असमकालिक फलन मुख्य() -> शून्य {
    संसाधन (स्रोत: निरस्तीकरणस्रोत = नया निरस्तीकरणस्रोत()) {
        स्थिर काम: कार्यफल<शून्य> = मानक.कार्य.विलंब(१०००, स्रोत.चिह्नलो());
        स्रोत.निरस्तकरो();
        प्रयास { प्रतीक्षा काम; }
        पकड़ो (दोष: निरस्तअपवाद) { लिखो("काम निरस्त हुआ"); }
    }
}
```

`नया निरस्तीकरणस्रोत(१०००)` एक सेकंड की समयसीमा वाला स्रोत बनाता है। समयसीमा
समाप्त होने पर `मानक.समयसीमाअपवाद` (Timeout exception) मिलता है। यह साधारण
निरस्तीकरण से अलग विफलता है। घड़ी एकदिश (Monotonic clock) है, इसलिए दीवार
घड़ी बदलने से अवधि नहीं बदलती। `नया निरस्तीकरणस्रोत(पूर्वचिह्न)` से जुड़े
स्रोत में पूर्व चिह्न का अनुरोध भी दिखाई देता है।

`मानक.कार्य.वर्तमानचिह्न()` वर्तमान कार्य के जीवनकाल का चिह्न देता है।
बिना स्पष्ट चिह्न के बनाया गया विलंब उसी जीवनकाल से जुड़ता है। स्रोत का
`बंदकरो()` पंजीकरण समाप्त करता है; वह अपने आप निरस्तीकरण नहीं करता। पहले से
हुआ अनुरोध चिह्न पर दिखाई देता रहता है।

केवल अपनी प्रतीक्षा रोकना (Cancel a wait) हो तो
`प्रतीक्षा कार्यफल.साथप्रतीक्षा(चिह्न)` लिखें। इससे मूल कार्य निरस्त नहीं
होता। उसका जीवनकाल मालिक के पास बना रहता है और मालिक उससे निकलने से पहले
उसके समाप्त होने की प्रतीक्षा करेगा।

## संसाधन और सफ़ाई

संरचित जीवनकाल (Structured lifetime) में फलन अपने आरम्भ किए हुए कार्यों के
समाप्त होने से पहले पूरा नहीं होता। संसाधन का क्षेत्र भी अपने बाल कार्यों
को जोड़ने के बाद ही संसाधन बन्द करता है। क्षेत्र से अपवाद निकलने पर उसके
बाल कार्यों को निरस्तीकरण का अनुरोध मिलता है। कार्य का बंधन छोड़ देने से
वह अलग, अनियन्त्रित पृष्ठभूमि कार्य नहीं बनता।

असमकालिक सफ़ाई (Async disposal) में `बंदकरो()` स्वयं कार्यफल लौटाता है:

```bhash
वर्ग साधन {
    सार्वजनिक असमकालिक फलन बंदकरो() -> शून्य {
        प्रतीक्षा मानक.कार्य.विलंब(१);
        लिखो("सफ़ाई पूरी");
    }
}

असमकालिक फलन मुख्य() -> शून्य {
    असमकालिक संसाधन (स: साधन = नया साधन()) {
        लिखो("संसाधन उपयोग में है");
    }
}
```

सफ़ाई एक बार चलती है। उसकी अपनी कार्य-श्रृंखला को जीवनकाल के निरस्तीकरण से
सुरक्षा मिलती है, ताकि अनुरोध आने पर आवश्यक बन्द करना न छूटे। स्पष्ट रूप
से दिया गया निरस्त चिह्न फिर भी जाँचा जाता है। सफ़ाई का अपवाद पहले से
लम्बित वापसी या अपवाद को बदल देता है, जैसे साधारण `अंततः` में होता है।
`अंततः` और `पकड़ो` में भी प्रतीक्षा की जा सकती है; `अंततः` से लौटना अब भी
अमान्य है। GC संसाधन को अपने आप बन्द नहीं करता।

## लक्ष्य और सीमाएँ

JVM, .NET और native लक्ष्य एक ही क्रम और अपवाद नियम प्रयोग करते हैं। Native
पर निलम्बित स्थानीय मान heap पर सुरक्षित रहते हैं और precise GC उन्हें
खोज सकता है। ब्राउज़र का प्रवेश बिन्दु JavaScript को रोके बिना कार्य चलाता
है। Stop पहले सहकारी निरस्तीकरण माँगता है; उत्तर न मिलने पर एक सेकंड बाद
worker समाप्त होता है। बलपूर्वक समाप्ति पर सफ़ाई की गारंटी नहीं है।

एक अनुप्रयोग में सामान्यतः अधिकतम १०२४ जीवित कार्य स्वीकार होते हैं। सफ़ाई
के लिए ३२ अतिरिक्त स्थान सुरक्षित हैं। सीमा समाप्त होना पकड़ने योग्य
अपवाद है। तुल्यकालिक HTTP/डेटाबेस फलन अभी भी तुल्यकालिक हैं; केवल उन्हें
असमकालिक फलन के भीतर बुलाने से वे nonblocking नहीं बनते। असमकालिक HTTP और
डेटाबेस परिवहन अगला अलग चरण है।

पूरे निर्णय और GC अनुबन्ध के लिए [स्वीकृत डिज़ाइन](../../docs/async-await-design.md)
देखें।

## कार्यसमूह और तैयार परिणाम (Task groups and settled results)

`मानक.कार्यसमूह.चलाओ()` एक `फलन()->कार्यफल<शून्य>` लेता है। callback कतार
में चलता है और समूह का परिणाम उसके सभी बच्चों की समाप्ति के बाद मिलता है।
समूह की प्रतीक्षा करें; बच्चों को चलाकर छोड़ देना अलग background lifetime नहीं
बनाता। उदाहरण:

```bhash
प्रतीक्षा मानक.कार्यसमूह.चलाओ(असमकालिक फलन()->शून्य {
    स्थिर पहला: कार्यफल<शून्य> = मानक.कार्य.विलंब(१०);
    स्थिर दूसरा: कार्यफल<शून्य> = मानक.कार्य.विलंब(२०);
    प्रतीक्षा पहला;
    प्रतीक्षा दूसरा;
});
```

`कार्यफल<पूर्णांक>.पूरा(४२)` पहले से सफल कार्य और
`कार्यफल<पूर्णांक>.असफल(नया अपवाद("दोष"))` पहले से विफल कार्य बनाता है।
`मानक.कार्य.पूरा()` शून्य परिणाम वाला सफल कार्य देता है। इनकी `प्रतीक्षा`
भी दूसरे तैयार काम को अवसर देती है। भविष्य में पूरा करने के लिए कोई सार्वजनिक
promise resolver अभी नहीं दिया गया है।

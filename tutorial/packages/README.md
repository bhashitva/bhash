# पुनः उपयोग योग्य संकुल और निर्भरताएँ (Reusable Packages and Dependencies)

संकुल (Package) किसी पुस्तकालय के स्रोत को नाम और संस्करण के साथ बाँटने का
तरीका है। निर्भरता (Dependency) उस पुस्तकालय का उपयोग करने वाले प्रोग्राम की
घोषणा है। अब स्रोत फ़ोल्डर की प्रतिलिपि बनाए बिना पुस्तकालय को अलग रखकर उपयोग
कर सकते हैं। यह संदर्भ-ट्यूटोरियल स्थानीय पुस्तकालय, पिन किया हुआ Git स्रोत,
लॉकफ़ाइल और सामान्य त्रुटियों को समझाता है।

## स्थानीय पुस्तकालय (Local Library)

[चलने योग्य उदाहरण](../../examples/packages/README.md) में तीन संकुल हैं:
`app` → `greetings` → `core`। `core` संख्या दुगुनी करता है और `greetings`
उसे अभिवादन के संदेश में उपयोग करता है।

[core/bhash.project](../../examples/packages/core/bhash.project) में:

```properties
name=example-core
kind=library
version=1.0.0
sources=src
```

`kind=library` बताता है कि यह साझा स्रोत है। पुस्तकालय के लिए `name` और
ठीक-ठीक संस्करण (Exact Version) अनिवार्य हैं। `1.0.0` स्वीकार्य है, पर
`^1.0.0`, `latest` और `1.*` स्वीकार्य नहीं हैं। पुस्तकालय में ऊपरी स्तर पर
`मुख्य` प्रवेश-कार्य नहीं होना चाहिए। उसे उपयोग करने वाला अनुप्रयोग अपना
`मुख्य` देता है।

[core/src/math.bhash](../../examples/packages/core/src/math.bhash):

```text
संकुल उदाहरण.गणना;

सार्वजनिक कार्य दुगुना(अंक: पूर्णांक) -> पूर्णांक {
    लौटाओ अंक * २;
}
```

यहाँ `संकुल उदाहरण.गणना` भाषा का नामस्थान (Namespace) है। घोषणा-पत्र का
`name=example-core` वितरण की पहचान है। दोनों नामों का एक जैसा होना आवश्यक
नहीं है। दूसरे नामस्थान से उपयोग करने योग्य घोषणा `सार्वजनिक` होनी चाहिए।

## निर्भरता की घोषणा (Dependency Declaration)

[greetings/bhash.project](../../examples/packages/greetings/bhash.project) में:

```properties
dependency.core.path=../core
dependency.core.version=1.0.0
```

`core` यहाँ घोषणा का स्थानीय उपनाम है। `path` इसी घोषणा-पत्र के फ़ोल्डर से
गिना जाता है। Windows पर भी `/` लिखें। यह भाषा में आयात का उपनाम नहीं बनाता।
पुस्तकालय का कार्य उपयोग करने के लिए सामान्य आयात लिखते हैं:

```text
आयात उदाहरण.गणना.दुगुना;
```

अप्रत्यक्ष निर्भरता (Transitive Dependency) अपने आप जुड़ती है: `app` केवल
`greetings` घोषित करता है, फिर भी निर्माण में उसका `core` भी आता है। एक ही
पुस्तकालय तक दो रास्तों से पहुँचने पर उसका स्रोत एक बार जुड़ता है। अलग स्थानों
पर एक ही संकुल नाम, गलत संस्करण और निर्भरता का चक्र त्रुटियाँ हैं। इस चरण में
निर्माण में उपस्थित सभी सार्वजनिक घोषणाओं का आयात संभव है; केवल प्रत्यक्ष
निर्भरता तक आयात सीमित करने का अलग नियम अभी नहीं है।

## लॉकफ़ाइल (Lockfile)

`bhash.lock` निर्भरताओं के घोषणा-पत्र और स्रोत की SHA-256 पहचान रखती है। इसे
स्वयं न लिखें। भंडार के मूल फ़ोल्डर से पहली बार लॉक बनाएँ:

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar deps lock examples/packages/app --offline
```

`deps lock` वर्तमान निर्भरताओं को जानबूझकर स्वीकार करता है। सफल होने पर ही
पुरानी लॉकफ़ाइल बदलती है। `--offline` नेटवर्क का उपयोग रोकता है। उदाहरण की
लॉकफ़ाइल पहले से भंडार में है, इसलिए सीधे जाँच और निष्पादन कर सकते हैं:

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar deps verify examples/packages/app
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run examples/packages/app
```

अपेक्षित परिणाम:

```text
नमस्ते, दुनिया! उत्तर: ४२
```

स्थानीय पुस्तकालय बदलने पर उपभोक्ता की पुरानी लॉकफ़ाइल मेल नहीं खाएगी। बदलाव
की समीक्षा करके `deps lock` दोबारा चलाएँ। स्रोत और नई लॉकफ़ाइल साथ जमा करें।
अनुप्रयोग के अपने स्रोत में बदलाव के लिए लॉक बदलना आवश्यक नहीं है। LF और
CRLF पंक्ति-अंत तथा आरंभिक UTF-8 BOM से स्रोत की पहचान नहीं बदलती। समान
सापेक्ष फ़ोल्डर व्यवस्था रखने पर लॉक अलग कंप्यूटर पर भी काम करती है।

## Git संशोधन पिन करना (Pinned Git Revision)

दूसरे भंडार से पुस्तकालय लेने के लिए `path` के स्थान पर `git` और पूरा `rev`
दें। नीचे बड़े अक्षरों वाले मान उदाहरण के स्थानधारक हैं; उन्हें वास्तविक URL
और पूरे कमिट हैश से बदलना आवश्यक है:

```properties
dependency.core.git=https://github.com/OWNER/REPOSITORY.git
dependency.core.rev=FULL_40_OR_64_CHARACTER_COMMIT_HASH
dependency.core.dir=packages/core
dependency.core.version=1.0.0
```

`dir` भंडार के अंदर संकुल का फ़ोल्डर है; न देने पर `.` माना जाता है।
`git rev-parse HEAD` से वर्तमान कमिट का पूरा हैश मिल सकता है। शाखा, टैग नाम
और छोटा हैश स्वीकार्य नहीं हैं। `version` चयनित कमिट के संकुल से मेल खाना
चाहिए। पहली बार `deps lock` बिना `--offline` चलाएँ। Git स्थापित होना चाहिए।
इस संस्करण में सार्वजनिक HTTPS तथा स्थानीय `file:` Git URI समर्थित हैं;
SSH, निजी भंडार और साइन-इन आधारित पहुँच अभी समर्थित नहीं हैं। साझा परियोजना
के लिए HTTPS चुनें; `file:` URI में कंप्यूटर का पूरा स्थानीय पथ आता है।

## बहाली और सत्यापन (Restore and Verify)

नए कंप्यूटर पर Git निर्भरताएँ बहाल करें, फिर निर्माण करें:

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar deps restore examples/packages/app
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar compile examples/packages/app
```

`restore` केवल लॉक से मेल खाने वाला स्रोत स्वीकार करता है; वह लॉक नहीं बदलता।
स्थानीय `path` वाले फ़ोल्डर पहले से उपलब्ध होने चाहिए। `verify` केवल जाँचता है।
`restore --offline` और `verify` नेटवर्क या फ़ाइलों में बदलाव नहीं करते।
साधारण निर्माण और संपादक विश्लेषण भी अपने आप निर्भरता डाउनलोड नहीं करते।

डाउनलोड किया स्रोत `.bhash/` कैश में रहता है। कैश जमा न करें; `bhash.project`
और `bhash.lock` जमा करें। कैश की प्रतिलिपि में बदलाव करने पर सत्यापन असफल होगा।
पुस्तकालय विकसित करते समय स्थानीय `path` उपयोग करें। क्षतिग्रस्त कैश प्रविष्टि
को अलग स्थान पर हटाकर `restore` चलाने से मूल स्रोत फिर प्राप्त कर सकते हैं।

## संपादक और त्रुटियाँ (Editor and Diagnostics)

विश्वसनीय VS Code कार्यक्षेत्र में कमांड पैलेट से
**Bhash: Update Dependencies Lock**, **Bhash: Restore Dependencies** या
**Bhash: Verify Dependencies** चलाएँ। सत्यापित पुस्तकालयों की पूर्णता-सूची,
स्वचालित आयात, हस्ताक्षर सहायता और F12 उपलब्ध होते हैं। संपादक में बिना सहेजा
स्रोत विश्लेषण में दिख सकता है, लेकिन डिस्क पर सहेजी निर्भरता को लॉक से मेल
खाना चाहिए।

| संकेत | अर्थ | उपाय |
| --- | --- | --- |
| `BH8001` | संकुल की घोषणा या पुस्तकालय का स्रोत अमान्य | संबंधित घोषणा या स्रोत सुधारें |
| `BH8002` | लॉक गायब, पुरानी या अमान्य | बदलाव की समीक्षा करके `deps lock` चलाएँ |
| `BH8003` | स्रोत लॉक से अलग | मूल स्रोत बहाल करें या बदलाव स्वीकार करके फिर लॉक करें |
| `BH8004` | चक्र, गलत संस्करण या नाम का टकराव | निर्भरता की घोषणा सुधारें |
| `BH8005` | Git, कैश या स्रोत-पथ की समस्या | पूरा कमिट, URL, Git उपलब्धता और कैश जाँचें |

अभी सार्वजनिक रजिस्ट्री, संस्करण-सीमा चयन और अलग से संकलित पुस्तकालय नहीं
हैं। निर्भरताएँ उसी संकलन में स्रोत के रूप में जुड़ती हैं। ब्राउज़र लक्ष्य की
सीमाएँ लागू रहती हैं; पुस्तकालय जोड़ने से स्थानीय फ़ाइल पहुँच नहीं मिलती।
पुनरुत्पादन का अर्थ समान सत्यापित स्रोत-समूह है; समान बाइनरी के लिए कंपाइलर,
JDK/.NET और निर्माण विकल्प भी स्थिर रखने होंगे।

विस्तृत नियम और सीमाएँ [अंग्रेज़ी पैकेज संदर्भ](../../docs/source-packages.md)
में हैं।

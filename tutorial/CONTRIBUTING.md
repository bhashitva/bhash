# ट्यूटोरियल लिखने की परंपराएँ (Tutorial Authoring Guide)

ट्यूटोरियल काम करते समय देखे जाने वाले संदर्भ हैं। हर नया विषय tutorial/ के भीतर अपना उपफ़ोल्डर पाए; lessons/ का क्रम, अवधि, अभ्यास या शिक्षक-योजना यहाँ न दोहराएँ। विषय के README को इस फ़ोल्डर के सूचकांक से जोड़ें।

- कथा हिन्दी में लिखें। हर अध्याय और हर फ़ंक्शन की शुरुआत में उसका परिचित अंग्रेज़ी नाम कोष्ठकों में दें; जैसे **लंबाई (Length)**। अंग्रेज़ी में जानने वाला पाठक इस संकेत से अपना विषय पहचान सके।
- फ़ंक्शन क्या करता है, कब उपयोगी है, पैरामीटर/वापसी प्रकार क्या हैं और कौन से ओवरलोड हैं, स्पष्ट करें। नाम वास्तविक library catalog से लें।
- छोटे code snippets के साथ पूरा चलाने योग्य .bhash उदाहरण दें। छोटे snippet को कहाँ रखना है और कौन सा आयात चाहिए, बताएँ; छिपी हुई setup न छोड़ें।
- अपेक्षित आउटपुट अलग .expected.txt में रखें। बदलने वाले समय/यादृच्छिक परिणामों को निश्चित उत्तर बताने की जगह बीज या गुण-जाँच से समझाएँ।
- error cases, encoding, Unicode, संख्यात्मक सीमाएँ और target के अंतर जहाँ लागू हों वहाँ समझाएँ। rounding और आधी-खुली सीमाओं को केवल अनुमान पर न लिखें।
- फ़ाइल लिखने वाले उदाहरण अलग अभ्यास directory में चलाएँ और overwrite व्यवहार पहले बताएँ। browser में unavailable सुविधाओं के लिए capability check दिखाएँ।
- compiler में नया feature सिर्फ़ ट्यूटोरियल के लिए न जोड़ें। समर्थित व्यवहार का ही संदर्भ दें।
- examples और दस्तावेज़ी snippets को एक समान रखें; JVM/CLR के लिए आउटपुट जाँचें और browser का परीक्षण या उसकी स्पष्ट सीमा दर्ज करें।

मानक पुस्तकालय के लिए coverage.json वर्तमान हस्ताक्षरों की सूची रखता है। verify.mjs library catalog से उसका मिलान करता है, snippets और पूरी example files की समानता जाँचता है, तथा सही compiler मिलने पर उदाहरण चलाकर आउटपुट मिलाता है। library बढ़े तो कथा, उदाहरण और सूची साथ अद्यतन करें।

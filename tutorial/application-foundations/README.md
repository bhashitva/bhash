# अनुप्रयोग का आधार (Application foundations)

इन पुस्तकालयों से संग्रह संसाधित करना, फ़ाइलों पर काम करना, विन्यास पढ़ना और
अपने कार्यक्रम की जाँच करना आसान होता है। उदाहरण पूर्ण कार्यक्रम हैं; Playground
में **Full program** चुनें। फ़ाइल, निर्देशिका और परिवेश के उदाहरण अपने कंप्यूटर पर चलाएँ।
सभी हस्ताक्षर तथा सीमाएँ [API संदर्भ](../../docs/application-foundations.md) में हैं।

## संग्रह के कार्य (Collection algorithms)

`संग्रह<त>` में `त` तत्व का प्रकार है। `तुलनाकार<त>.तुलना(क,ख)` ऋणात्मक,
शून्य या धनात्मक मान देता है। `पूर्णांकक्रम` पहले से उपलब्ध आरोही पूर्णांक तुलना है।
`चयनक<त>.चुनो(मानक)` बताता है कि कोई तत्व चुना जाए या नहीं।

| कार्य | अर्थ |
| --- | --- |
| `प्रतिलिपि` (Copy) | मूल क्रम में नई सूची; भीतर की वस्तुएँ साझा रहती हैं |
| `उलटो` (Reverse) | उलटे क्रम की नई सूची |
| `छाँटो` (Filter) | नियम से मेल खाने वाले तत्व |
| `कोई` (Any) | पहला मेल मिलते ही सत्य; खाली सूची पर असत्य |
| `सभी` (All) | पहला अमेल मिलते ही असत्य; खाली सूची पर सत्य |
| `खोजो` (Find index) | पहले मेल का सूचकांक, नहीं मिले तो -१ |
| `गिनो` (Count matches) | मेल खाने वाले तत्वों की संख्या |
| `क्रमित` (Stable sort) | नई क्रमबद्ध सूची; समान तत्वों का पुराना क्रम बना रहता है |
| `द्विआधारीखोज` (Binary search) | पहले से क्रमबद्ध सूची में पहले समान तत्व का सूचकांक, नहीं मिले तो -१ |

`रूपांतरक<क,ख>.बदलो` एक मान को दूसरे प्रकार/मान में बदलता है।
`संचायक<क,ख>.जोड़ो` पिछले संचय और अगले तत्व से नया संचय बनाता है।

| कार्य | अर्थ |
| --- | --- |
| `रूपांतरण<क,ख>.बदलो` (Map) | प्रत्येक तत्व का रूपांतरण |
| `रूपांतरण<क,ख>.संचित` (Fold) | आरंभिक मान से बाएँ से दाएँ संचय |
| `समूहन<क,ख>.समूहित` (Group by) | चयनित कुंजी के अनुसार सूचियों का मानचित्र |

[पूरा चलने योग्य उदाहरण](../../examples/foundations/collections.test.bhash) हर
कार्य का आह्वान करता है। इसे चलाने पर कोई त्रुटि न होना सभी अपेक्षाओं के सही होने
का संकेत है। तुलना या चयन करते समय मूल सूची को न बदलें। द्विआधारी खोज के लिए
उसी तुलनाकार से सूची को पहले क्रमित करें।

## संसाधन का जीवनकाल (Scoped resource cleanup)

`बंदनीय.बंदकरो` (Close) संसाधन छोड़ने का अनुबंध है। `संसाधन` दायरा इसे अपने
आप बुलाता है। सामान्य समाप्ति, `लौटाओ`, `विराम`, `जारी` और अपवाद में भी सफाई
होती है। अंदर के दायरे का संसाधन पहले बंद होता है।

```bhash
आयात मानक.प्रवाह;
कार्य मुख्य() -> शून्य {
    संसाधन (फ: प्रवाह = प्रवाह.लेखन("संदेश.txt")) {
        फ.पाठलिखो("नमस्ते, दुनिया!\n");
        फ.भेजो();
    }
}
```

यह उदाहरण `संदेश.txt` बनाता है या उसकी पुरानी सामग्री बदलता है। अपने चुने पथ
पर ही चलाएँ। [नियंत्रण-प्रवाह की जाँच](../../examples/foundations/resources.test.bhash)
अपवाद तथा लौटने पर सफाई दिखाती है। यदि मुख्य काम और सफाई दोनों में अपवाद हो,
तो मौजूदा `अंततः` की तरह सफाई का अपवाद बाहर जाता है।

## प्रवाह (Streams)

| कार्य | अर्थ |
| --- | --- |
| `प्रवाह.पठन` (Open read) | मौजूद फ़ाइल से पढ़ने का प्रवाह |
| `प्रवाह.लेखन` (Open write) | फ़ाइल बनाने/पुरानी सामग्री बदलने का प्रवाह |
| `पढ़ो` (Read bytes) | अधिकतम माँगी गई बाइटें; अंत पर खाली बफ़र |
| `बाइटलिखो` (Write bytes) | बफ़र की बाइटें लिखना |
| `पाठलिखो` (Write UTF-8 text) | पाठ को UTF-8 में लिखना |
| `भेजो` (Flush) | बफ़र में रुका लेखन भेजना; डिस्क पर स्थायित्व की गारंटी नहीं |
| `बंदकरो` (Close) | प्रवाह बंद करना; दोबारा बंद करना सुरक्षित |

एक पढ़ने/लिखने में अधिकतम १०४८५७६ बाइटें लें। कुल फ़ाइल इससे बड़ी हो सकती है।
शून्य बाइट माँगना फ़ाइल के अंत की जाँच नहीं है। UTF-8 अक्षर दो बफ़रों में बँट
सकता है, इसलिए मनमाने हिस्से को अलग-अलग पाठ में बदलना सुरक्षित नहीं है।

```bhash
आयात मानक.प्रवाह;
कार्य मुख्य() -> शून्य {
    संसाधन (मूल: प्रवाह = प्रवाह.पठन("मूल.bin")) {
        संसाधन (फल: प्रवाह = प्रवाह.लेखन("प्रतिलिपि.bin")) {
            मान भाग: बाइटबफ़र = मूल.पढ़ो(८१९२);
            जबतक (भाग.आकार > ०) {
                फल.बाइटलिखो(भाग);
                भाग = मूल.पढ़ो(८१९२);
            }
        }
    }
}
```

मूल और प्रतिलिपि के लिए अलग फ़ाइलें चुनें; यह प्रतिलिपि की पुरानी सामग्री बदलता
है। `संसाधन` से फ़ाइलों का जीवनकाल स्पष्ट रखें; स्मृति का कचरा-संग्रह फ़ाइल को
तुरंत बंद करने का विकल्प नहीं है।

## पथ और निर्देशिका (Paths and directories)

| कार्य | अर्थ |
| --- | --- |
| `पथ.सामान्य` (Normalize lexical path) | अतिरिक्त `/` और `.` हटाना; `..` बचता है |
| `पथ.जोड़ो` (Join) | मूल पथ में सापेक्ष नाम जोड़ना |
| `पथ.नाम` (Base name) | अंतिम भाग |
| `पथ.जनक` (Parent) | जनक पथ |
| `निर्देशिका.है` (Directory exists) | निर्देशिका मौजूद है या नहीं |
| `निर्देशिका.बनाओ` (Create directory) | एक नई निर्देशिका; जनक पहले मौजूद हो |
| `निर्देशिका.नाम` (List entries) | सीधे बच्चों के नाम; क्रम निश्चित नहीं |
| `निर्देशिका.फ़ाइलहटाओ` (Delete file) | मौजूदा साधारण फ़ाइल हटाना |
| `निर्देशिका.हटाओ` (Remove empty directory) | केवल खाली निर्देशिका हटाना |

```bhash
आयात मानक.पथ;
कार्य मुख्य() -> शून्य {
    स्थिर नाम: पाठ = पथ.जोड़ो("काम/", "./फल.txt");
    लिखो(पथ.सामान्य(नाम), पथ.नाम(नाम), पथ.जनक(नाम));
}
```

पथ सहायक सभी कंप्यूटरों पर `/` लेते हैं। `\\`, UNC पथ, खाली पथ और NUL
अस्वीकार होते हैं। ये केवल पाठ बदलते हैं: फ़ाइल खोलना, symlink हल करना या
सुरक्षित निर्देशिका में रहने की जाँच नहीं करते। हटाने के कार्य अपरिवर्तनीय हो
सकते हैं; अपने कार्यक्रम द्वारा बनाए पथों पर ही उदाहरण चलाएँ।

यह उदाहरण नई `भाष-निर्देशिका-उदाहरण` निर्देशिका बनाता है और अंत में केवल अपनी
बनाई फ़ाइल तथा खाली निर्देशिका हटाता है। वह नाम पहले से मौजूद हो तो निर्माण
विफल होगा; मौजूदा निर्देशिका को इस उदाहरण के लिए इस्तेमाल न करें।

```bhash
आयात मानक.पथ;
आयात मानक.निर्देशिका;
आयात मानक.फ़ाइल;
कार्य मुख्य() -> शून्य {
    स्थिर मूल: पाठ = "भाष-निर्देशिका-उदाहरण";
    निर्देशिका.बनाओ(मूल);
    स्थिर नाम: पाठ = पथ.जोड़ो(मूल,"फल.txt");
    प्रयास {
        फ़ाइल.पाठलिखो(नाम,"भाष");
        लिखो(निर्देशिका.है(मूल));
        प्रत्येक (अ: पाठ में निर्देशिका.नाम(मूल)) { लिखो(अ); }
    } अंततः {
        यदि (फ़ाइल.है(नाम)) { निर्देशिका.फ़ाइलहटाओ(नाम); }
        निर्देशिका.हटाओ(मूल);
    }
}
```

## विन्यास (Configuration)

| कार्य | अर्थ |
| --- | --- |
| `नया विन्यास()` (Empty configuration) | खाली विन्यास |
| `रखो` (Set) | नाम का मान रखना/बदलना |
| `पढ़ो` (Get with default) | मान न होने पर वैकल्पिक मान; खाली पाठ भी वास्तविक मान है |
| `जेसनपढ़ो` (Parse JSON configuration) | केवल पाठ मानों वाला JSON object पढ़ना |
| `तर्कपढ़ो` (Parse arguments) | दी गई सूची के `--नाम=मान` पढ़ना |
| `तर्क` (Program arguments) | वास्तविक कार्यक्रम के तर्क पढ़ना |
| `परिवेश` (Environment variable) | परिवेश का मान या वैकल्पिक मान लेना |

```bhash
आयात मानक.विन्यास;
कार्य मुख्य() -> शून्य {
    स्थिर व: विन्यास = विन्यास.जेसनपढ़ो("{\"स्थान\":\"भारत\"}");
    व.रखो("भाषा", "हिन्दी");
    स्थिर त: विन्यास = विन्यास.तर्कपढ़ो(नया सूची<पाठ>{"--नाम=भाष"});
    लिखो(व.पढ़ो("भाषा", ""), त.पढ़ो("नाम", ""));
}
```

`विन्यास.तर्क()` को `--नाम=मान` के साथ बने executable/JAR/DLL में उपयोग करें।
`विन्यास.परिवेश("BHASH_MODE", "development")` परिवेश से वैकल्पिक सेटिंग लेता
है। किस स्रोत को प्राथमिकता मिले, यह कार्यक्रम स्पष्ट रूप से तय करता है।
एक नाम दोबारा आने पर अंतिम मान रखा जाता है।

## लेखा (Structured logging)

`स्तर` (Threshold) में ० debug, १ info, २ warning, ३ error, ४ बंद है।
`घटनालिखो` (Write event) संदेश और अतिरिक्त क्षेत्रों की JSON पंक्ति stderr
में लिखता है। `सूचना` (Info) बिना अतिरिक्त क्षेत्रों की सूचना है। सामान्य
कार्यक्रम के stdout परिणाम इससे अलग रहते हैं।

```bhash
आयात मानक.लेखा;
कार्य मुख्य() -> शून्य {
    लेखा.स्तर(१);
    लेखा.सूचना("काम शुरू");
    लेखा.घटनालिखो(२, "फिर प्रयास करें", नया मानचित्र<पाठ,सर्ववस्तु>{"प्रयास":२});
    लेखा.स्तर(४);
}
```

पासवर्ड, token और निजी जानकारी अपने आप लेखा में न डालें। लेखन समकालिक है;
यह संस्करण फ़ाइल rotation या पृष्ठभूमि logging नहीं देता।

## परीक्षण (Testing)

`सत्यहै` (Assert condition) गलत शर्त पर अपने संदेश के साथ अपवाद फेंकता है।
`बराबर` (Assert equal) पूर्णांक, पाठ और तार्किक मानों के लिए अलग overload देता
है। अपवाद भी `प्रयास`/`पकड़ो` से जाँचे जा सकते हैं।

```bhash
आयात मानक.परीक्षण;
कार्य मुख्य() -> शून्य {
    परीक्षण.बराबर(४, २ + २);
    परीक्षण.बराबर("भारत", "भारत");
    परीक्षण.बराबर(सत्य, ३ > २);
    परीक्षण.सत्यहै(५ > १, "पाँच बड़ा होना चाहिए।");
}
```

इसे `जोड़.test.bhash` में रखें और compiler का `test` command चलाएँ।

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar test examples/foundations --target native --timeout 30
```

`--target jvm` तथा `--target clr` भी उपलब्ध हैं। प्रत्येक फ़ाइल/परीक्षण-project
अलग process में चलता है। एक की विफलता के बाद बाकी चलते हैं। परिणाम में pass,
fail और कुल कार्यक्रमों की संख्या मिलती है। assertion की संख्या अलग से नहीं
गिनी जाती। समय-सीमा के बाद अटका कार्यक्रम बंद किया जाता है।

साझा library जाँचने के लिए `नाम.test/bhash.project` वाला परीक्षण project बनाएँ
और सामान्य package dependency घोषित करें। प्रक्रिया अलग है, पर फ़ाइल तंत्र
अलग sandbox नहीं है; परीक्षणों को अस्थायी, नियंत्रित पथ दें।

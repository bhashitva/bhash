# विकल्पसमूह, मिलान और परिणाम (Tagged unions, pattern matching and Result)

## विकल्पसमूह (Tagged union)

जब किसी मान की कई निश्चित अवस्थाएँ हों और हर अवस्था के साथ अलग जानकारी जुड़ी हो, तब `विकल्पसमूह` चुनें। उदाहरण के लिए छात्र की खोज में छात्र मिल सकता है, अनुपस्थित हो सकता है या खोज असफल हो सकती है। केवल एक `तार्किक` मान इन तीनों स्थितियों और उनके विवरण को सुरक्षित ढंग से नहीं दिखा पाता।

```bhash
विकल्पसमूह छात्रखोज {
    मिला(विद्यार्थी: छात्र);
    अनुपस्थित();
    असफल(संदेश: पाठ);
}
```

`छात्रखोज.मिला(नया छात्र("आशा", ९०))` नया मान बनाता है। बिना payload वाला विकल्प भी कोष्ठक से बनता है: `छात्रखोज.अनुपस्थित()`। `नया छात्रखोज()` नहीं लिखें। विकल्पों का परिवार बन्द है: कोई अलग वर्ग उसका विस्तार नहीं कर सकता। Payload अचल है; उसमें साधारण परिवर्तनशील वस्तु का संदर्भ हो तो उस वस्तु के अपने नियम लागू रहते हैं।

## मान देने वाला मिलान (Match expression)

[पूरा छात्र-खोज और Result उदाहरण](results.bhash) तथा [अपेक्षित आउटपुट](results.expected.txt) देखें। `मिलान` चयनकर्ता को केवल एक बार मूल्यांकित करता है और ऊपर से नीचे पहली स्वीकार की गई शाखा का मान देता है।

```bhash
लौटाओ मिलान (उत्तर) {
    विकल्प छात्रखोज.मिला(छात्र(स्थिर नाम, स्थिर अंक)) यदि (अंक >= ८०) => नाम + ": उत्कृष्ट",
    विकल्प छात्रखोज.मिला(स्थिर विद्यार्थी) => विद्यार्थी.नाम,
    विकल्प छात्रखोज.अनुपस्थित() => "छात्र नहीं मिला",
    विकल्प छात्रखोज.असफल(स्थिर संदेश) => संदेश,
};
```

`स्थिर नाम` नया स्थानीय अचल बन्धन है। वह उसी शाखा में उपलब्ध होता है। `छात्र(...)` अभिलेख के क्षेत्रों को घोषणा के क्रम में खोलता है। `_` उस स्थान के किसी भी मान को स्वीकार करता है और कोई नाम नहीं बनाता। `स्थिर _` न लिखें।

`यदि (...)` शाखा की अतिरिक्त शर्त (guard) है। Guard में फलन बुला सकते हैं; वह सामान्य अपवाद भी फेंक सकता है। Guard गलत हो तो अगली शाखा देखी जाती है। Guard वाली शाखा सम्पूर्णता की गिनती में नहीं आती: ऊपर के उदाहरण में दूसरा `मिला` इसलिए आवश्यक है। Guard में `सत्य` लिख देने से भी यह नियम नहीं बदलता।

## कथन वाला मिलान (Match statement)

जब शाखा को केवल एक मान लौटाने के बजाय कई काम करने हों, `=>` की जगह `: { ... }` लिखें। दोनों शैलियों में हर सम्भव मान को सम्भालना आवश्यक है। चयनित शाखा के बाद अगली शाखा नहीं चलती। शाखा में `लौटाओ` अपने फलन से लौटता है; `विराम` मिलान से बाहर आता है और `जारी` बाहर के चक्र की अगली आवृत्ति पर जाता है।

```bhash
मिलान (उत्तर) {
    विकल्प मानक.परिणाम.सफल(स्थिर मूल्य): { लिखो("उत्तर:", मूल्य); }
    विकल्प मानक.परिणाम.असफल(स्थिर दोष): { लिखो("दोष:", दोष); }
}
```

## सम्पूर्णता और प्रकार प्रतिरूप (Exhaustiveness and type patterns)

दोनों मिलान रूपों में `रिक्त`, `सत्य`, `असत्य`, पूर्णांक, पाठ, परिगणना सदस्य, अभिलेख और nested विकल्प प्रतिरूप उपलब्ध हैं। दशमलव literal, मनमाने class/property/list प्रतिरूप और OR/range प्रतिरूप अभी उपलब्ध नहीं हैं। `शेष` अन्तिम बिना guard वाली शाखा है; इसका उपयोग सोचकर करें, क्योंकि भविष्य में जोड़ा गया विकल्प भी उसमें चला जाएगा।

`स्थिर उपलब्ध: छात्रखोज` केवल उस गैर-रिक्त प्रकार के मान को स्वीकार करता है। साधारण `स्थिर उपलब्ध` रिक्त सहित किसी भी मान को बाँधता है। Strict null-safety में `छात्रखोज?` के लिए `रिक्त` अलग सम्भावना है। पुराने reference व्यवहार में भी रिक्त को सम्भालना पड़ता है।

```bhash
स्थिर उत्तर: छात्रखोज? = रिक्त;
लिखो(मिलान (उत्तर) {
    विकल्प रिक्त => "अभी खोज नहीं हुई",
    विकल्प स्थिर उपलब्ध: छात्रखोज => विवरण(उपलब्ध),
});
```

छूटी शाखा पर `BH3312`, पहले से पूरी तरह ढकी शाखा पर `BH3311`, गलत प्रतिरूप पर `BH3310` और असंगत शाखा-मानों पर `BH3314` मिलता है। शाखाओं का एक संगत परिणाम प्रकार होना चाहिए। अलग प्रकार जानबूझकर लौटाने हों तो परिणाम का `सर्ववस्तु` जैसा स्पष्ट साझा प्रकार दें। बहुत जटिल प्रतिरूपों की सीमित जाँच `BH3313` दे सकती है; तब मिलान को छोटे भागों में बाँटें।

## सामान्य और बन्द प्रकार (Generics and closed types)

```bhash
विकल्पसमूह खोज<त> { मिला(मूल्य: त); अनुपस्थित(); }
स्थिर उत्तर = खोज<पूर्णांक>.मिला(७);
```

निर्माण में बन्द प्रकार `खोज<पूर्णांक>` लिखें। चयनकर्ता का बन्द परिवार ज्ञात हो तो प्रतिरूप में `खोज.मिला(...)` पर्याप्त है। `सर्ववस्तु` चयनकर्ता के प्रतिरूप में पूरा बन्द प्रकार दें, जैसे `खोज<पूर्णांक>.मिला(स्थिर अंक)`। अलग type arguments अलग nominal परिवार हैं। Generic अभिलेख के प्रतिरूप में भी type arguments स्पष्ट लिखें।

## प्रकारयुक्त परिणाम (Typed Result)

`मानक.परिणाम<त, द>` में दो विकल्प हैं: `सफल(मूल्य: त)` और `असफल(दोष: द)`। अपेक्षित व्यावसायिक विफलता को स्पष्ट डेटा बनाने के लिए इसका उपयोग करें। उदाहरण में शून्य से भाग देने पर `असफल` मिलता है; caller दोनों शाखाएँ सम्भालता है। यह सामान्य exceptions, cancellation या database API की त्रुटियों को अपने आप नहीं बदलता।

`मानक.इकाई` बिना क्षेत्रों वाला अचल अभिलेख है। सफल काम का कोई उपयोगी मान न हो तो `मानक.परिणाम<मानक.इकाई, पाठ>` और `नया मानक.इकाई()` चुनें। `परिणाम<शून्य, पाठ>` अमान्य है। अपने आप unwrap करने या त्रुटि आगे बढ़ाने वाला `?` operator इस सुविधा का भाग नहीं है।

## असमकालिक परिणाम (Asynchronous Result)

[चलने योग्य async उदाहरण](async-result.bhash) और [उसका आउटपुट](async-result.expected.txt) देखें। `असमकालिक फलन ... -> मानक.परिणाम<पाठ, पाठ>` सामान्य `कार्यफल<परिणाम<...>>` देता है। पहले उस कार्य की `प्रतीक्षा` करें, फिर मिले Result पर मिलान करें। Async फलन में guard और शाखा-मान में भी `प्रतीक्षा` चलती है।

`असफल` के साथ पूरा हुआ कार्य सफलतापूर्वक पूरा हुआ task है, जिसका domain परिणाम विफलता है। फेंका गया अपवाद task fault है और निरस्तीकरण अलग task अवस्था है। संसाधन-सफ़ाई, `अंततः` और cancellation के मौजूदा नियम लागू रहते हैं।

## समानता और स्मृति-सुरक्षा (Equality and GC safety)

एक ही बन्द परिवार, एक ही विकल्प और समान payload वाले मान बराबर होते हैं। पाठ ordinal रूप से, nested अभिलेख/विकल्प संरचनात्मक रूप से और साधारण परिवर्तनशील वस्तुएँ पहचान से तुलना करती हैं। इसलिए समान अचल परिणामों को मानचित्र या समुच्चय की कुंजी बना सकते हैं। Raw hash, आन्तरिक class ID और विकल्प के क्रम को JSON/database/wire format न बनाएँ; बाहरी representation का स्पष्ट versioned mapping रखें।

JVM, .NET, native Linux/Windows और साप्ताहिक Apple Silicon validation में साझा semantics उपयोग होते हैं। Native में हर विकल्प का अलग, निश्चित GC layout है। चयनकर्ता, payload, captures और async frames की references संग्रहण तथा अपवाद-सफ़ाई में सुरक्षित रहती हैं। Application programmer को allocation/free नहीं करना पड़ता। Native का आन्तरिक runtime ABI अब 18 है; पुराने native runtime और नए compiler के generated code को न मिलाएँ।

## उदाहरण चलाना (Running the examples)

हर फ़ाइल पूर्ण क्रमानुदेश है। Standalone compiler से:

```sh
java -jar bhash-compiler.jar compile tutorial/tagged-unions/results.bhash --target jvm -o results.jar
java -jar results.jar
java -jar bhash-compiler.jar compile tutorial/tagged-unions/results.bhash --target clr -o out/results-clr
java -jar bhash-compiler.jar compile tutorial/tagged-unions/results.bhash --target native -o out/results
```

.NET output में `BhashProgram.dll` को `dotnet` से चलाएँ। Windows native output के लिए `.exe` नाम दें। वही दोनों फ़ाइलें VS Code के Build/Run और Playground के **Full Program** mode में भी चलती हैं। Jupyter में पहले विकल्पसमूह/अभिलेख/फलन घोषणाएँ चलाएँ, फिर उदाहरण के `मुख्य` के कथन अलग cell में चलाएँ; scalar बन्धन अगले cells में उपलब्ध रहते हैं। मौजूदा Jupyter kernel में object बन्धन cell-local हैं; विकल्प का मान और उसका मिलान एक ही cell में रखें, अथवा घोषणा वाले cell में फलन बनाएँ और अगले cell में उस फलन के लौटाए मान पर मिलान करें। आवश्यक host/toolchain setup के लिए [build निर्देश](../../README.md) देखें।

पूर्ण निर्णय और सीमाएँ: [हिन्दी डिज़ाइन](../../docs/tagged-unions-pattern-matching-design.md), [English design](../../docs/tagged-unions-pattern-matching-design.en.md)।

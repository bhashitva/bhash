# SQLite डेटाबेस (SQLite Database)

(SQLite) छोटी अनुप्रयोग-फ़ाइल, स्थानीय सूची, विद्यालय का अभिलेख या डेस्कटॉप उपकरण
बनाते समय डेटा को तालिकाओं में रखना उपयोगी है। यह पुस्तकालय SQL को तैयार करता है,
मान अलग बाँधता है और पंक्तियाँ पढ़ता है। अलग डेटाबेस सर्वर स्थापित नहीं करना पड़ता।
SQL के `SELECT`, `INSERT` जैसे शब्द SQLite के अंग्रेज़ी शब्द ही हैं; भाष के API हिन्दी में हैं।
JVM, .NET CLR और native Linux/Windows x64 तथा macOS ARM64 पर SQLite 3.54.1 मिलता है।
ब्राउज़र में डेटाबेस खोलना उपलब्ध नहीं है और पकड़ने योग्य `अपवाद` आता है।

## खोलना और संसाधन सँभालना (Open and Resource Cleanup)

(Open) `एसक्यूलाइट.खोलो(पथ: पाठ) -> डेटाबेस` स्थानीय फ़ाइल खोलता है या बनाता है।
`":memory:"` से हर कनेक्शन का अलग अस्थायी डेटाबेस बनता है। `नया डेटाबेस(पथ)` भी वही
काम करता है। `एसक्यूलाइट.संस्करण() -> पाठ` से `"3.54.1"` मिलता है। फ़ाइल नाम जैसे
`"विद्यालय.db"` प्रक्रिया के वर्तमान फ़ोल्डर से माने जाते हैं; मूल फ़ोल्डर पहले से होना चाहिए।
URI, `file:`, `jdbc:`, NUL, `?` और `#` वाले पथ इस पहले संस्करण में स्वीकार नहीं होते।

(Prepare) `ड.तैयार(एसक्यूएल: पाठ) -> कथन` SQL जाँचकर तैयार कथन देता है। एक बार में
एक ही कथन दें। मानों के लिए `?` रखें। `"SELECT name FROM student WHERE id=?"` में
प्रश्नचिह्न का मान बाद में बाँधें। उपयोगकर्ता का पाठ जोड़कर SQL बनाना injection का जोखिम है।
तालिका/स्तंभ के नाम `?` से नहीं बाँधे जा सकते; ऐसे नाम अपने विश्वसनीय कोड में चुनें।

(Close) `क.बंदकरो()` कथन और `ड.बंदकरो()` कनेक्शन छोड़ते हैं। बार-बार बंद करना सुरक्षित है।
कनेक्शन बंद करने पर उसके सभी कथन बंद और अधूरा लेनदेन वापस हो जाता है। इसके बाद पढ़ना
या SQL चलाना त्रुटि है। `संसाधन` ब्लॉक अपने अंत, `लौटाओ` और अपवाद पर `बंदकरो` बुलाता है।
GC भाष की स्मृति सँभालता है; डेटाबेस ताले और लेनदेन के लिए `संसाधन` आवश्यक है।

## मान बाँधना (Parameter Binding)

(Bind) सूचकांक **१ से** शुरू होता है। `बंधनसंख्या() -> पूर्णांक` से `?` की संख्या मिलती है।
हर मापदंड बाँधें, NULL भी स्पष्ट रूप से दें। नया मान बाँधना केवल नए या रीसेट किए कथन पर संभव है।

| विधि और उदाहरण | अर्थ |
| --- | --- |
| `क.पूर्णांकरखो(१,४२)` | (Bind Integer) signed 64-bit `पूर्णांक` को INTEGER रखता है। |
| `क.दशमलवरखो(२,१.२५)` | (Bind Real) binary64 `दशमलव` रखता है; NaN और अनंत स्वीकार नहीं हैं। |
| `क.तार्किकरखो(३,सत्य)` | (Bind Boolean) सत्य को १ और असत्य को ० रखता है। |
| `क.पाठरखो(४,"भारत😀")` | (Bind Text) पाठ को UTF-8 TEXT रखता है; उद्धरण SQL में नहीं बदलते। |
| `क.बाइटरखो(५,नया बाइटबफ़र(०))` | (Bind Blob) बाइटों की प्रतिलिपि रखता है; खाली बफ़र NULL नहीं है। |
| `क.रिक्तरखो(६)` | (Bind Null) SQL NULL रखता है; यह खाली पाठ या शून्य संख्या से अलग है। |

(Snapshot) पाठ और बाइट बंधन के समय कॉपी होते हैं। बाद में मूल बफ़र बदलने से SQL का मान
नहीं बदलता। SQL column affinity के कारण तालिका में वास्तविक storage class बदल सकती है;
पढ़ते समय `प्रकार` देखकर वास्तविक प्रकार समझें। तारीख को अपनी तय पद्धति से ISO पाठ या
epoch पूर्णांक रखें; मनमाने वस्तु-संदर्भ अपने-आप serialize नहीं होते।

## चलाना और पढ़ना (Execute and Read)

(Execute) `क.चलाओ() -> पूर्णांक` बिना परिणाम-स्तंभ वाला CREATE/INSERT/UPDATE/DELETE
चलाता है। परिणाम `total_changes64` का अंतर है, जिसमें trigger/cascade के बदलाव भी शामिल
होते हैं। यह नया row id नहीं है। पंक्ति लौटाने वाले SQL, `RETURNING` सहित, के लिए
`क.अगला() -> तार्किक` बुलाएँ। हर सत्य परिणाम पर वर्तमान पंक्ति उपलब्ध है; असत्य पर समाप्त।
असत्य के बाद फिर `अगला` बुलाने से वही SQL दोबारा नहीं चलता।

(Column) स्तंभ सूचकांक **० से** शुरू होता है। metadata पंक्ति आने से पहले भी पढ़ सकते हैं।
पंक्ति के मान पढ़ने के लिए पहले `अगला()` का सत्य परिणाम चाहिए।

| विधि और उदाहरण | अर्थ |
| --- | --- |
| `क.स्तंभसंख्या()` | (Column Count) परिणाम-स्तंभों की संख्या देता है। |
| `क.स्तंभनाम(०)` | (Column Name) SQL alias सहित स्तंभ का नाम देता है। |
| `क.प्रकार(०)` | (Storage Class) `पूर्णांक`, `दशमलव`, `पाठ`, `बाइटबफ़र` या `रिक्त` देता है। |
| `क.रिक्तहै(५)` | (Is Null) SQL NULL की जाँच करता है। |
| `क.पूर्णांकलो(०)` | (Read Integer) केवल INTEGER पढ़ता है; `"42"` या REAL अपने-आप नहीं बदलता। |
| `क.दशमलवलो(१)` | (Read Real) REAL या INTEGER को binary64 में पढ़ता है। बड़े पूर्णांकों में rounding हो सकती है। |
| `क.तार्किकलो(२)` | (Read Boolean) INTEGER ०/१ पढ़ता है; २ भी त्रुटि है। |
| `क.पाठलो(३)` | (Read Text) TEXT की सख्त UTF-8 जाँच करता है; अमान्य bytes त्रुटि हैं। |
| `क.बाइटलो(४)` | (Read Blob) BLOB की अलग प्रतिलिपि देता है; कथन बंद होने पर भी बफ़र वैध रहता है। |

(Null) NULL पर getter त्रुटि देता है। पहले `रिक्तहै` जाँचें और अनुप्रयोग में उचित विकल्प चुनें।
SQL में स्पष्ट `CAST` देकर रूपांतरण माँग सकते हैं, लेकिन SQLite की conversion नीति और
भाष की सख्त getter नीति अलग हैं। दशमलव सटीक वित्तीय दशमलव नहीं है।

(Reset) `क.रीसेट()` वर्तमान cursor छोड़ता है और वही बंधन बचाकर कथन तैयार करता है।
`क.बंधनमिटाओ()` रीसेट/तैयार कथन के सभी मापदंड अनबँधे करता है; फिर सभी बाँधें। SQL त्रुटि
के बाद रीसेट आवश्यक है। निम्न पूरा उदाहरण हर bind/read API, metadata, reset और close चलाता है।
इसे [values.bhash](../../examples/sqlite/values.bhash) के रूप में भी चलाएँ।

```bhash
// SPDX-License-Identifier: Apache-2.0
आयात मानक.एसक्यूलाइट; आयात मानक.डेटाबेस; आयात मानक.कथन;
कार्य मुख्य() -> शून्य {
    लिखो(एसक्यूलाइट.संस्करण());
    संसाधन (ड: डेटाबेस = एसक्यूलाइट.खोलो(":memory:")) {
        संसाधन (क: कथन = ड.तैयार("SELECT ? AS अंक, ?, ?, ?, ?, ?")) {
            लिखो(क.बंधनसंख्या(),क.स्तंभसंख्या(),क.स्तंभनाम(०));
            क.पूर्णांकरखो(१,४२); क.दशमलवरखो(२,१.२५); क.तार्किकरखो(३,सत्य);
            क.पाठरखो(४,"भारत😀"); क.बाइटरखो(५,नया बाइटबफ़र(०)); क.रिक्तरखो(६);
            जबतक (क.अगला()) {
                लिखो(क.पूर्णांकलो(०),क.दशमलवलो(१),क.तार्किकलो(२),क.पाठलो(३));
                लिखो(क.प्रकार(४),क.बाइटलो(४).आकार,क.रिक्तहै(५));
            }
            क.रीसेट(); क.बंधनमिटाओ();
            क.रिक्तरखो(१); क.रिक्तरखो(२); क.रिक्तरखो(३);
            क.रिक्तरखो(४); क.रिक्तरखो(५); क.रिक्तरखो(६);
            यदि (क.अगला()) { लिखो(क.प्रकार(०)); }
        }
    }
    स्थिर अलग: डेटाबेस = नया डेटाबेस(":memory:");
    स्थिर कथ: कथन = अलग.तैयार("CREATE TABLE t(id INTEGER)");
    लिखो(कथ.चलाओ()); कथ.बंदकरो(); अलग.बंदकरो();
}
```

अपेक्षित परिणाम:

```text
3.54.1
६ ६ अंक
४२ १.२५ सत्य भारत😀
बाइटबफ़र ० सत्य
रिक्त
०
```

## लेनदेन (Transactions)

(Begin Transaction) `ड.लेनदेन() -> लेनदेन` **BEGIN DEFERRED** शुरू करता है। एक कनेक्शन
पर एक ही सक्रिय लेनदेन रखें। nested transaction और savepoint अभी नहीं हैं।
`ल.सहेजो() -> शून्य` (Commit) बदलाव स्थायी करता है। `ल.वापसलो() -> शून्य` (Rollback)
बदलाव वापस करता है। `ल.बंदकरो() -> शून्य` (Dispose) अधूरा लेनदेन वापस करता है।
इसलिए commit स्पष्ट रखें; केवल ब्लॉक समाप्त होना commit नहीं है। Commit विफल हो तो
scope सक्रिय रहता है ताकि सफाई rollback कर सके। पुराने समाप्त scope को बंद करने से नया
लेनदेन वापस नहीं होता। समाप्त scope पर फिर commit/rollback त्रुटि है।

(Cursor Invalidation) लेनदेन शुरू/समाप्त होने पर पहले से चले कथन के cursor अमान्य होते हैं।
दोबारा उपयोग से पहले `रीसेट()` करें। अभी तक न चले कथन तैयार रहते हैं। नीचे १ सहेजा जाता है;
२, ३ और ४ वापस होते हैं। देखें [transactions.bhash](../../examples/sqlite/transactions.bhash)।

```bhash
// SPDX-License-Identifier: Apache-2.0
आयात मानक.एसक्यूलाइट; आयात मानक.डेटाबेस; आयात मानक.कथन; आयात मानक.लेनदेन;
कार्य जोड़ो(ड: डेटाबेस, अंक: पूर्णांक) -> शून्य {
    संसाधन (क: कथन = ड.तैयार("INSERT INTO account VALUES (?,?)")) {
        क.पूर्णांकरखो(१,अंक); क.पाठरखो(२,"मनोज"); क.चलाओ();
    }
}
कार्य मुख्य() -> शून्य {
    संसाधन (ड: डेटाबेस = एसक्यूलाइट.खोलो(":memory:")) {
        संसाधन (क: कथन = ड.तैयार("CREATE TABLE account(id INTEGER PRIMARY KEY, name TEXT)")) { क.चलाओ(); }
        संसाधन (ल: लेनदेन = ड.लेनदेन()) { जोड़ो(ड,१); ल.सहेजो(); }
        संसाधन (ल: लेनदेन = ड.लेनदेन()) { जोड़ो(ड,२); ल.वापसलो(); }
        स्थिर ल: लेनदेन = ड.लेनदेन(); जोड़ो(ड,३); ल.बंदकरो();
        प्रयास {
            संसाधन (रद्द: लेनदेन = ड.लेनदेन()) { जोड़ो(ड,४); फेंको नया अपवाद("रद्द करें"); }
        } पकड़ो (ग: अपवाद) { लिखो(ग.संदेश); }
        संसाधन (क: कथन = ड.तैयार("SELECT id, name FROM account ORDER BY id")) {
            जबतक (क.अगला()) { लिखो(क.पूर्णांकलो(०),क.पाठलो(१)); }
        }
    }
}
```

अपेक्षित परिणाम:

```text
रद्द करें
१ मनोज
```

## चलाना और वितरण (Run and Distribution)

repository से compiler बनाने के बाद:

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run examples/sqlite/values.bhash --target jvm
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run examples/sqlite/values.bhash --target clr
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run examples/sqlite/values.bhash --target native
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar test examples/sqlite --target native
```

(Distribution) JVM JAR में JDBC driver और उसकी platform libraries रहती हैं; Java 17+ और
लिखने योग्य temporary directory चाहिए। CLR का पूरा output फ़ोल्डर भेजें; उसके साथ verified
SQLite libraries और .NET 10 runtime चाहिए। Native executable में SQLite जुड़ा रहता है;
अलग SQLite, JVM या .NET की जरूरत नहीं। compilation के समय सामान्य target toolchain चाहिए।
ब्राउज़र API खोलने पर `ब्राउज़र लक्ष्य पर SQLite उपलब्ध नहीं है।` मिलता है।

## सीमाएँ और त्रुटियाँ (Limits and Errors)

(Limits) एक प्रक्रिया में एक साथ ३२ कनेक्शन, १२८ कथन, प्रति कथन ९९९ मापदंड और २५६ स्तंभ
हैं। SQL अधिकतम ६४ KiB, मान और पंक्ति के संयुक्त पाठ/blob ८ MiB तक हैं; SQLite record
limit भी लागू है। व्यस्त डेटाबेस पर ५ सेकंड तक प्रतीक्षा होती है। यह तुल्यकालिक API है;
लंबा SQL UI thread रोक सकता है। बंद संसाधन इन सीमाओं से निकल जाते हैं।

(Errors) सभी targets पर समान हिन्दी `अपवाद` मिलता है: बाधा उल्लंघन, व्यस्त डेटाबेस,
गलत प्रकार, NULL, सीमा, सूचकांक, बंद संसाधन आदि। `प्रयास`/`पकड़ो` से सँभालें और
`ग.संदेश` पढ़ें। पूरी engine-specific अंग्रेज़ी error string पर निर्भर न रहें।
[offline.test.bhash](../../examples/sqlite/offline.test.bhash) parameter injection से बचाव
का चलने योग्य परीक्षण है। पूर्ण contract, वितरण checksums और cleanup विवरण
[SQLite संदर्भ](../../docs/sqlite.md) में हैं। `डेटानियम`, `डेटाअवस्था` और `डाटातंत्र`
आंतरिक implementation हैं; अनुप्रयोग को ऊपर दिए चार सार्वजनिक प्रकारों का उपयोग करना चाहिए।

(Rollback Only) लेनदेन के भीतर SQL चलाने में engine त्रुटि आए तो scope केवल rollback योग्य हो जाता है। उसके बाद SQL या commit से पहले `वापसलो`/`बंदकरो` करें। SQLite अपने-आप rollback करे तब अगला SQL चुपचाप autocommit में नहीं चलेगा; केवल कथन रीसेट करना पर्याप्त नहीं है।

(Portable SQL) साझा SQL व्यवहार में SQLite का मुख्य SQL, JSON, FTS5 और R*Tree हैं। JDBC के कुछ अतिरिक्त compile-time विकल्प सभी targets पर नहीं हैं। समान version से सभी वैकल्पिक SQL extensions समान नहीं हो जाते; आवश्यक हो तो `PRAGMA compile_options` देखें।

# पुस्तक का रखरखाव (Maintaining the book)

[विषय सूची](README.md)

पुस्तक की भूमिका सीखने का क्रम समझाना है। भाषा का सटीक व्यवहार
`docs/` में, फलनों और उदाहरणों का विषयवार संदर्भ `tutorial/` में,
और चलने वाला पूरा स्रोत `examples/` या `lessons/` में रखें।
पुस्तक से उन्हीं फ़ाइलों के सापेक्ष लिंक दें। इससे किसी उदाहरण की
दो स्वतंत्र प्रतियाँ बदलने की जरूरत घटती है। छोटे अभ्यास जो केवल
पुस्तक के हैं, `book/examples/` में रखें।

जब कोई सार्वजनिक सुविधा बदलती है तो संबंधित PR में यह जाँच करें।

1. पहचानें कि पाठक पहले किस अवधारणा को जानता होगा। नीचे के मानचित्र में
   संबंधित अध्याय चुनें। नई अवधारणा हो तो अध्याय में छोटा परिचय, एक
   चलने योग्य लिंक और एक अभ्यास जोड़ें।
2. हिन्दी कथा के साथ परिचित अंग्रेज़ी नाम पहली बार कोष्ठक में दें।
   कोड में वर्तमान वाक्यरचना और वास्तविक API नाम उपयोग करें। किसी
   अस्थायी लक्ष्य सीमा को पाठक के लिए स्पष्ट करें।
   पुस्तक से सीधे जुड़े संदर्भ की व्याख्या हिन्दी में रखें। यदि अंग्रेज़ी
   मूल भी रखा है, तो उसी पृष्ठ पर उसके हर व्याख्यात्मक अनुच्छेद के बाद
   `**हिन्दी:**` अनुच्छेद दें। मूल बदलने पर हिन्दी पाठ भी उसी बदलाव में
   सुधारें। कोड, आदेश, API नाम और मौजूदा अनुभाग लिंक सुरक्षित रखें।
3. अध्याय का लिंक, विषय सूची और आगे-पीछे के लिंक साथ बदलें। किसी
   निर्देश में संस्करण संख्या तभी रखें जब व्यवहार उसी रिलीज़ से शुरू हुआ हो।
4. यदि नया उदाहरण `book/examples/` में है तो उसी आधार नाम की
   `.expected.txt` फ़ाइल जोड़ें। पुराने उदाहरण का लिंक तभी बदलें जब नया
   लिंक उसी काम का पूरा स्रोत देता हो।
5. लिंक और नमूने जाँचें। बदले उदाहरण को संबंधित लक्ष्य पर चलाएँ।
   बाहरी सेवा, डेटाबेस या उपकरण की जरूरत हो तो निर्देश में दें।

```sh
python scripts/check_book.py

```

पहला आदेश स्थानीय लिंक और हर छोटे उदाहरण की अपेक्षित फ़ाइल देखता
है। बाकी आदेश चुने गए लक्ष्य पर नमूने चलाकर उनका UTF-8 आउटपुट
मिलाते हैं। इनके लिए बना compiler JAR और संबंधित लक्ष्य उपकरण चाहिए।
रिपॉज़िटरी की managed CI में लिंक और JVM/CLR के नमूने जाँचे जाते हैं।
विषयवार ट्यूटोरियल के अपने परीक्षण और बाहरी लिंक की समीक्षा भी करें।


## ऑफ़लाइन संस्करण बनाना

Git, Python 3.12 और Node.js की मदद से किसी प्रतिबद्ध Git संशोधन से PDF और
ऑफ़लाइन ZIP बनाएँ। उदाहरण में संस्करण `1.0.0` है।

```sh
python -m pip install -r book/requirements.txt
python -m playwright install chromium
npm pack @fontsource/noto-sans-devanagari@5.3.0
python scripts/check_book.py
python scripts/build_book.py --version 1.0.0 --font-package fontsource-noto-sans-devanagari-5.3.0.tgz
```

Linux पर Chromium की सिस्टम निर्भरताओं के लिए `python -m playwright install --with-deps chromium`
चलाएँ। किसी दूसरे प्रतिबद्ध संशोधन को पढ़ने के लिए `--revision` दें। परिणाम
`target/book/` में मिलेंगे। PDF और ZIP पर स्रोत संशोधन अंकित होता है। PDF में
निर्माण समय का मेटाडेटा बदल सकता है।

GitHub Actions में **Hindi book exports** चलाकर उसी संशोधन और संस्करण की फ़ाइलें
लें। प्रकाशित करने से पहले PDF के पृष्ठों में मात्राएँ, संयुक्ताक्षर, कोड और
पृष्ठ संख्या देखें। विषय सूची से एक अध्याय और उदाहरण के परिशिष्ट तक जाएँ।
ZIP निकालकर इंटरनेट बंद होने पर `index.html` से ट्यूटोरियल और उदाहरण खोलें।
उसी संशोधन पर `book-hi-<संस्करण>` टैग से GitHub रिलीज़ बनाएँ और PDF, ZIP तथा
`SHA256SUMS` जोड़ें। इसे नवीनतम कंपाइलर रिलीज़ के रूप में चिह्नित करने का विकल्प
खाली रखें। नई पुस्तक प्रकाशित होने पर विषय सूची के दोनों डाउनलोड लिंक अद्यतन करें।

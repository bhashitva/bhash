# ८. पूरी वेब सेवा और वितरण (Build and ship an application)

[← पिछला अध्याय](07-io-and-async.md) · [विषय सूची](README.md)

अब तक आपके पास काम का अभिलेख, सत्यापन नियम, संग्रह, डेटाबेस और परीक्षण
हैं। इस अध्याय में उन्हें HTTP API के रूप में जोड़ें। पहले स्थानीय रूप
से चलाएँ ताकि किसी दूसरे उपयोगकर्ता या सर्वर पर असर पड़े बिना व्यवहार
देख सकें।

## काम बनाएँ, पढ़ें और जाँचें (Typed web API)

[प्रकारयुक्त कार्य API](../examples/typed-api/README.md) पाँच छोटे
संकुलों में विभाजित है। उसके [अनुबंध](../examples/typed-api/schema.json)
से Bhash अभिलेख, JSON सत्यापन, मार्ग और OpenAPI दस्तावेज़ बनते हैं।
डेटाबेस और HTTP कोड एक ही प्रकार वाले अभिलेख पढ़ते हैं। इसे नीचे की
क्रमबद्ध जाँच से समझें।

1. [हिन्दी API ट्यूटोरियल](../tutorial/typed-api/README.md) के आदेशों से
   SQLite वाली सेवा चलाएँ। `POST /api/tasks` को [नमूना JSON](../tutorial/typed-api/task.json)
   भेजें। `201` मिलने पर `GET /api/tasks/1` से वही काम पढ़ें।
2. प्राथमिकता `9` भेजें और देखें कि `422` मिलता है। उसी पहचान को
   दोबारा भेजने और गलत JSON भेजने में क्या अंतर है?
3. `GET /openapi.json` में प्राथमिकता की सीमा देखें। फिर ट्यूटोरियल का
   नया क्षेत्र जोड़ने वाला अभ्यास करें। पुराने डेटा का डिफ़ॉल्ट और नए
   गलत मान की अस्वीकृति दोनों जाँचें।
4. JVM, CLR और native में जहाँ उपकरण उपलब्ध हैं, वही परीक्षण चलाएँ।
   मार्गक परीक्षण असली SQL और JSON चलाता है। HTTP परीक्षण वास्तविक
   loopback अनुरोध भी भेजता है।

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar test examples/typed-api --target jvm
```

ब्राउज़र और Jupyter में [अभिलेख वाला छोटा रूप](../tutorial/typed-api/models.bhash)
चल सकता है। HTTP सर्वर और डेटाबेस वाली पूरी परियोजना desktop लक्ष्य
चाहती है।

## उपयोगकर्ता की पहचान और अधिकार (Authentication and authorization)

कार्य API सीखने के लिए स्थानीय उदाहरण है। उपयोगकर्ता जोड़ने पर पहचान
(कौन है) और अधिकार (क्या कर सकता है) अलग प्रश्न हैं।
[प्रमाणीकरण ट्यूटोरियल](../tutorial/authentication/README.md) में
कूटशब्द हैश, सुरक्षित cookie, सत्र, अनुमति और CSRF के अभ्यास हैं।
[नोट्स अनुप्रयोग](../examples/auth-sessions/README.md) में प्रवेश
करने वाले और न करने वाले उपयोगकर्ता से एक ही अनुरोध करें। फिर सामान्य
और व्यवस्थापक भूमिका से परिणाम मिलाएँ। HTTP सर्वर और routing की
बुनियाद [वेब अनुप्रयोग ट्यूटोरियल](../tutorial/web-applications/README.md)
में है।

## निर्माण से वितरण तक (Packaging and deployment)

लक्ष्य तय होने पर `compile` से परिणाम बनाएँ। JAR के लिए Java,
CLR आउटपुट के लिए उपयुक्त .NET रनटाइम और native के लिए उपयुक्त
ऑपरेटिंग सिस्टम व आर्किटेक्चर चाहिए। अलग मशीन पर परीक्षण करें।
नेटिव वितरण में `native package`, manifest और host जाँच
[वितरण मार्गदर्शिका](../docs/native-releases.md) में हैं।
[Windows](../docs/native-windows.md) और [Apple Silicon](../docs/native-macos.md)
की अलग आवश्यकताएँ पढ़ें।

डेटाबेस पथ, credentials और TLS प्रमाणपत्र का विन्यास तैनाती के
परिवेश में रखें। सार्वजनिक HTTP सेवा के लिए reverse proxy, HTTPS,
प्रवेश नियंत्रण और सीमाएँ [सर्वर अनुबंध](../docs/web-applications.md)
और [नमूना तैनाती](../examples/web-tasks/README.md) के साथ जाँचें।
पुरानी तालिका का बैकअप लें, फिर माइग्रेशन पहले एक परीक्षण प्रति पर
चलाएँ।

**अंतिम अभ्यास।** नया कार्य क्षेत्र जोड़ें, पुराने डेटा पर माइग्रेशन
चलाएँ, दो गलत अनुरोधों के परीक्षण जोड़ें और साफ़ वातावरण में पैकेज से
सेवा चलाएँ। किसी साथी को सिर्फ़ अपना README और OpenAPI दें। यदि वह
API का सही अनुरोध बना सके तो आपका दस्तावेज़ भी परीक्षण में सफल है।

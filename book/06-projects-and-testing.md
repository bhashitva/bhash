# ६. परियोजना, परीक्षण और डिबगिंग (Projects and testing)

[← पिछला अध्याय](05-libraries-and-resources.md) · [विषय सूची](README.md) · [अगला अध्याय →](07-io-and-async.md)

एक फ़ाइल में छोटा अभ्यास पढ़ना आसान है। जब डेटा, नियम और उपयोगकर्ता
से बातचीत बढ़ें तो इन्हें अलग स्रोत फ़ाइलों में रखें। `संकुल` नामों
को समूह देता है। `आयात` दूसरे संकुल का सार्वजनिक नाम लाता है।
`bhash.project` बताता है कि एक निर्माण में कौन से स्रोत और निर्भरताएँ
शामिल हैं।

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run examples/multi-file --target jvm
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar deps verify examples/packages/app
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar run examples/packages/app --target jvm
```

पहली परियोजना में अलग स्रोत फ़ाइलें खोजें। दूसरी में ऐप और उसकी दो
स्रोत लाइब्रेरी अलग संकुल हैं। संस्करण, पथ और सामग्री के जाँचे गए
मान `bhash.lock` में हैं। स्थानीय लाइब्रेरी बदलने पर पहले बदलाव
पढ़ें, फिर जानबूझकर `deps lock` चलाएँ। अपरिचित निर्भरता होने पर
[संकुल ट्यूटोरियल](../tutorial/packages/README.md) में स्थानीय और
ठीक Git revision वाले उदाहरण देखें।

## जाँच लिखें (Assertions and test runner)

कार्य की प्राथमिकता १ से ५ तक हो तो `१`, `५` और `६` अलग
परीक्षण हैं। केवल सबसे आसान मामला चलाने से सीमा पर गलती छूट सकती है।
`परीक्षण.बराबर` वास्तविक और अपेक्षित परिणाम मिलाता है।
`परीक्षण.सत्यहै` किसी आवश्यक शर्त की जाँच करता है।
`*.test.bhash` या `*.test/bhash.project` को अपना `मुख्य` दें।

```sh
java -jar target/bhash-compiler-0.1.0-SNAPSHOT.jar test examples/foundations --target jvm
```

इसे `--target clr` या `--target native` पर भी दोहरा सकते हैं।
[परीक्षण और अनुप्रयोग आधार](../docs/application-foundations.md) में
समयसीमा, अलग प्रक्रिया और विफल आउटपुट के नियम हैं। वहीं `विन्यास` से
तर्क व परिवेश पढ़ने और `लेखा` से संरचित लॉग लिखने के उदाहरण हैं।
पासवर्ड और निजी डेटा लॉग में डालने से बचें।

## रुककर मान देखें (Debugger)

गलत परिणाम वाली पंक्ति से पहले breakpoint लगाएँ। [Native debugging
उदाहरण](../examples/native/debugging.bhash) को VS Code में खोलें।
समर्थित होस्ट पर **Bhash: Debug Native** चुनें। स्टेप करते समय किसी
फलन के प्रवेश, बदले मान और लौटने की पंक्ति देखें। Watch में चलती
अभिव्यक्ति को पढ़कर अपना अनुमान मिलाएँ।
[VS Code सेटअप](../editors/vscode/README.md) और
[हिन्दी डिबगिंग निर्देश](../docs/native-vscode-debug.md) में होस्ट,
डिबगर और Watch की सीमाएँ हैं।

**खुद आज़माएँ।** किसी मौजूदा परीक्षण की अपेक्षित संख्या जानबूझकर
बदलें। विफलता पढ़ें और अपेक्षा वापस ठीक करें। फिर उसी परीक्षण में एक
सीमा वाला मामला जोड़ें। नए संकलक पर लौटते समय पुराने उदाहरणों के लिए
[सामूहिक निर्माण निर्देश](../docs/building-examples.md) उपयोग करें।

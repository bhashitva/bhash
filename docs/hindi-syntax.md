# फलन और संग्रह-प्रथम पुनरावृत्ति (Functions and Collection-first Iteration)

भाष में फलन घोषित करने का कीवर्ड अब **`फलन` (Function)** है। संग्रह पर
पुनरावृत्ति में पहले संग्रह और फिर उसका तत्व आता है, जिससे कथन हिन्दी के
शब्दक्रम के अनुसार पढ़ा जा सके: “संख्याएँ में प्रत्येक अंक”।

```bhash
फलन दुगुना(अंक: पूर्णांक) -> पूर्णांक { लौटाओ अंक * २; }

फलन मुख्य() -> शून्य {
    स्थिर संख्याएँ: सूची<पूर्णांक> = नया सूची<पूर्णांक>{१,२,३};
    प्रत्येक (संख्याएँ में अंक: पूर्णांक) { लिखो(दुगुना(अंक)); }

    स्थिर तालिका: मानचित्र<पाठ,पूर्णांक> = नया मानचित्र<पाठ,पूर्णांक>{"भारत":१};
    प्रत्येक (तालिका में कुंजी: पाठ, मूल्य: पूर्णांक) { लिखो(कुंजी, मूल्य); }
}
```

**फलन (Function)** — यही कीवर्ड शीर्ष-स्तरीय फलन, वर्ग के सदस्य, साझा सदस्य,
अधिलेखित सदस्य और अनुबंध के हस्ताक्षर में उपयोग होता है। `फलन` अब आरक्षित
शब्द है; इसे चर या प्रकार का नाम नहीं बना सकते। इससे बड़े नाम, जैसे
`फलनमान`, सामान्य पहचानकर्ता हैं। `कार्य` अब आरक्षित शब्द नहीं है।

**प्रत्येक (For-each)** — सरणी, सूची, बाइटबफ़र और मानचित्र में संग्रह पहले
आता है। संग्रह की जगह फलन का आह्वान या कोई दूसरा संग्रह देने वाला व्यंजक
भी लिख सकते हैं। मानचित्र की एक बाइंडिंग कुंजी देती है; दो बाइंडिंग क्रमशः
कुंजी और मूल्य देती हैं। दोनों बाइंडिंग `में` के बाद आती हैं।

संग्रह का व्यंजक केवल एक बार चलता है, लूप के चर घोषित होने से पहले। चर
केवल लूप के शरीर में उपलब्ध हैं। पुनरावृत्ति का क्रम, तत्वों के प्रकार,
संग्रह बदलने के नियम, `विराम`, `जारी`, अपवाद और स्मृति प्रबंधन नहीं बदले हैं।

## पुराना स्रोत बदलना (Source Migration)

यह जानबूझकर स्रोत-संगतता तोड़ने वाला परिवर्तन है। पुराने रूप स्वीकार नहीं
होते और उनके लिए कोई compatibility mode नहीं है:

| पुराना रूप | नया रूप |
| --- | --- |
| `कार्य जोड़ो(...) -> पूर्णांक { ... }` | `फलन जोड़ो(...) -> पूर्णांक { ... }` |
| `प्रत्येक (अ: पूर्णांक में अंक) { ... }` | `प्रत्येक (अंक में अ: पूर्णांक) { ... }` |
| `प्रत्येक (क: पाठ, व: पूर्णांक में तालिका) { ... }` | `प्रत्येक (तालिका में क: पाठ, व: पूर्णांक) { ... }` |

अपने स्रोत और source dependencies दोनों बदलें। `कार्य` को संदेश, टिप्पणी,
साधारण हिन्दी गद्य या बड़े नामों के भीतर बदलने की आवश्यकता नहीं है। यदि
स्थानीय पैकेज का स्रोत बदला है, उसकी lockfile सामान्य dependency workflow
से फिर बनाएँ; पुराने integrity hashes को हाथ से हटाकर जाँच बंद न करें।

Compiler को `mvn clean verify` से फिर बनाएँ। VS Code और playground को भी
नए compiler के साथ अद्यतन करना आवश्यक है: पुराने प्रकाशित संस्करण नए
कीवर्ड को नहीं पहचानेंगे। पहले से बनी JAR, .NET assembly या native executable
को फिर चलाने के लिए स्रोत बदलना आवश्यक नहीं है; अगला संकलन नया रूप माँगेगा।
Playground में सहेजे गए पुराने drafts और साझा source links का पाठ भी बदलें।

The shared parser accepts only `फलन` declarations and
`प्रत्येक (collectionExpression में binding: Type[, value: Type])`.
All backends receive the same checked loop representation; this change introduces
no new runtime ABI or execution semantics. Rebuild the compiler, bundled library,
editor tooling and browser host together when deploying the new syntax.

**हिन्दी:** साझा parser केवल `फलन` और `प्रत्येक (संग्रह में बंधन: प्रकार[, मान: प्रकार])` स्वीकार करता है। सभी backend को एक ही जाँचा हुआ चक्र मिलता है। runtime ABI और निष्पादन नियम वही हैं। नई वाक्यरचना तैनात करते समय संकलक, bundled पुस्तकालय, संपादक और ब्राउज़र होस्ट साथ बनाएँ।
